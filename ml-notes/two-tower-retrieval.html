Two-Tower Retrieval

Say it in 30s: Two-tower retrieval learns separate user and item embeddings so the score is a dot product. Train with sampled softmax and in-batch negatives; correct with logQ so popular items are not oversampled as negatives. At serve time, precompute all item vectors, index them with ANN (HNSW/FAISS), run the user tower once per request, and retrieve top-kkk — that's how you hit billion-scale catalogs under ~20ms.

Key points

  • Decoupled serving: item tower offline → ANN; user tower online → one lookup. Ranking with full crosses happens only on kkk candidates.
  • Loss: contrastive / sampled softmax over positive + negatives; in-batch negatives scale with batch size.
  • logQ correction: subtract ln⁡Q(item)\ln Q(\text{item})lnQ(item) from negative logits so head items do not dominate the denominator.
  • Complements: graph retrieval, BM25, trending — union before the ranker.

Common follow-ups / traps

  • "Why not score all pairs with a cross-encoder?" → Quadratic cost; cross-encoders are for rerank/hundreds, not billions.
  • "What if the user embedding is stale?" → Blend batch user vector with real-time session features in the user tower or a small ranker boost.

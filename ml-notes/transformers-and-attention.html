Transformers & Attention

LLMs: the architecture underneath nearly every modern language model.

The transformer is a stack of identical blocks, each mixing information across positions (attention) and then transforming each position independently (feed-forward network), with residual connections and normalization wrapped around both. Interview questions on it reduce to a short list: what are the tensor shapes, why the scaling factor, how does the model know word order, what does the mask do, what is cached at inference, and where does the quadratic cost come from. This chapter walks that list in order.

What you'll be able to say after this chapter
  • Write scaled dot-product attention with correct shapes and justify the 1/dk1/\sqrt{d_k}1/dk​​ factor.
  • Explain multi-head attention, and why positional information must be injected.
  • Contrast sinusoidal, RoPE and ALiBi positional schemes.
  • Distinguish encoder-only, decoder-only and encoder-decoder models, and say what causal masking does.
  • Explain pre- vs post-norm, the FFN's role, the O(n2)O(n^2)O(n2) cost, KV caching, FlashAttention, and MQA/GQA.
Notation used throughout
  • nnn = sequence length, dmodeld_{model}dmodel​ = hidden size, hhh = number of heads, dkd_kdk​ = per-head query/key size, dvd_vdv​ = per-head value size, LLL = number of layers, BBB = batch size.
  • X∈Rn×dmodelX \in \mathbb{R}^{n \times d_{model}}X∈Rn×dmodel​ = the matrix of token representations entering a layer (one row per token).

#From text to vectors: tokenization and embeddings

A model operates on integers, not strings. Tokenization maps text to a sequence of IDs from a fixed vocabulary (typically tens of thousands to a few hundred thousand entries).

Scheme Idea Trade-off
Word-level One ID per word Huge vocabulary; out-of-vocabulary words are unrepresentable
Character / byte-level One ID per character or byte No OOV, but sequences become long, and attention cost grows as n2n^2n2
Subword (BPE, WordPiece, Unigram) Frequent strings become single tokens; rare words split into pieces Compromise used by most LLMs; byte-level BPE variants can represent any input

BPE builds its vocabulary by repeatedly merging the most frequent adjacent pair of symbols in a training corpus. The result is learned from data, so tokenization quality varies by language and domain: text in languages or formats that are rare in the tokenizer's training corpus may need many more tokens per word, which raises cost and shortens the effective context.

An embedding table E∈R∣V∣×dmodelE \in \mathbb{R}^{|V| \times d_{model}}E∈R∣V∣×dmodel​ turns each token ID into a row vector. These vectors are learned jointly with the rest of the network. Many models tie the input embedding matrix to the output (unembedding) matrix to save parameters; this is common but not universal.

Interview angle

Tokenization explains several odd behaviors: difficulty with character-level tasks (counting letters, reversing strings), uneven cost across languages, and sensitivity to whitespace and formatting. Linking a failure to the tokenizer, with the caveat that it is one factor among several, is a strong answer.

#Scaled dot-product attention

Each token representation is projected three ways with learned matrices:

Q=XWQ,K=XWK,V=XWVQ = XW_Q,\qquad K = XW_K,\qquad V = XW_VQ=XWQ​,K=XWK​,V=XWV​

with WQ,WK∈Rdmodel×dkW_Q, W_K \in \mathbb{R}^{d_{model}\times d_k}WQ​,WK​∈Rdmodel​×dk​ and WV∈Rdmodel×dvW_V \in \mathbb{R}^{d_{model}\times d_v}WV​∈Rdmodel​×dv​. Intuition: a query is "what am I looking for," a key is "what do I contain, for matching purposes," and a value is "what I hand over if matched."

#Why divide by dk\sqrt{d_k}dk​​

Suppose the components of a query qqq and key kkk are independent with mean 0 and variance 1. Then q⋅k=∑i=1dkqikiq\cdot k = \sum_{i=1}^{d_k} q_i k_iq⋅k=∑i=1dk​​qi​ki​ is a sum of dkd_kdk​ independent terms, each with mean 0 and variance 1, so

Var(q⋅k)=dk,std=dk.\mathrm{Var}(q\cdot k) = d_k,\qquad \text{std} = \sqrt{d_k}.Var(q⋅k)=dk​,std=dk​​.

Dividing by dk\sqrt{d_k}dk​​ restores unit variance. Without it, for large dkd_kdk​ the logits have a large spread, so the softmax is pushed toward a near one-hot distribution. In that saturated regime the softmax gradients are tiny for most entries, which slows or destabilizes learning. The variance argument is a heuristic that assumes roughly unit-variance, independent components at initialization; trained weights need not satisfy it, but the scaling remains the standard remedy.

Interview angle

Say the one-line derivation: dot product of dkd_kdk​ unit-variance terms has variance dkd_kdk​. Then name the consequence: saturated softmax, vanishing gradients. State the assumption (zero mean, unit variance, independence) rather than presenting it as exact.

#What the softmax output means

Row iii of the softmax is a set of non-negative weights summing to 1 over positions. The output for token iii is ∑jaijvj\sum_j a_{ij} v_j∑j​aij​vj​, a convex combination of value vectors. Attention is therefore a content-based, differentiable lookup: the mixing weights are computed from the data, unlike a convolution whose weights are fixed per offset.

Attention itself has no notion of order: permuting the rows of XXX permutes the output rows in the same way (it is permutation-equivariant). Order must be injected separately; see positional encodings below.

#Multi-head attention

Instead of one attention with dmodeld_{model}dmodel​-sized keys, use hhh heads, each with its own projections, typically with dk=dv=dmodel/hd_k = d_v = d_{model}/hdk​=dv​=dmodel​/h:

headi=Attention(XWQ(i),XWK(i),XWV(i)),MHA(X)=[head1;… ;headh] WO\text{head}_i = \text{Attention}(XW_Q^{(i)}, XW_K^{(i)}, XW_V^{(i)}),\qquad \text{MHA}(X) = [\text{head}_1;\dots;\text{head}_h]\,W_Oheadi​=Attention(XWQ(i)​,XWK(i)​,XWV(i)​),MHA(X)=[head1​;…;headh​]WO​

with WO∈Rhdv×dmodelW_O \in \mathbb{R}^{h d_v \times d_{model}}WO​∈Rhdv​×dmodel​. Concatenating heads gives n×hdvn \times h d_vn×hdv​, and WOW_OWO​ maps back to n×dmodeln \times d_{model}n×dmodel​.

  • Why: a single softmax produces one weighting per query; multiple heads let the layer attend to different positions or different kinds of relations in parallel, each in a lower-dimensional subspace. Empirically, different heads often specialize (for example, positional or syntactic patterns), though many heads can be pruned with little loss, so "every head is essential" is not a safe claim.
  • Cost: with dk=dmodel/hd_k = d_{model}/hdk​=dmodel​/h, total compute and parameter count are about the same as one full-width head. The attention parameters per layer are 4dmodel24 d_{model}^24dmodel2​ (WQ,WK,WV,WOW_Q, W_K, W_V, W_OWQ​,WK​,WV​,WO​, ignoring biases).

#Positional encodings

Because attention is permutation-equivariant, "dog bites man" and "man bites dog" would look identical as bags of tokens. Position must enter somewhere.

Scheme Where applied How Notes
Learned absolute Added to input embeddings A trainable vector per position Simple; limited to the maximum trained length
Sinusoidal (original) Added to input embeddings Fixed sines/cosines of different frequencies No parameters; extrapolation to longer lengths is often weak in practice
RoPE Applied to QQQ and KKK inside each attention layer Rotates query/key coordinate pairs by a position-dependent angle Encodes relative offset in the dot product; widely used in open LLMs
ALiBi Added to attention scores Subtracts a penalty proportional to distance, with a per-head slope No position embeddings; designed for length extrapolation

Sinusoidal. For position pospospos and dimension pair index iii:

PE(pos,2i)=sin⁡ ⁣(pos100002i/dmodel),PE(pos,2i+1)=cos⁡ ⁣(pos100002i/dmodel)PE_{(pos,2i)} = \sin\!\left(\frac{pos}{10000^{2i/d_{model}}}\right),\qquad PE_{(pos,2i+1)} = \cos\!\left(\frac{pos}{10000^{2i/d_{model}}}\right)PE(pos,2i)​=sin(100002i/dmodel​pos​),PE(pos,2i+1)​=cos(100002i/dmodel​pos​)

Low iii gives high frequency (fine position), high iii gives low frequency (coarse position). A useful property: PEpos+kPE_{pos+k}PEpos+k​ is a linear function (a rotation within each sin/cos pair) of PEposPE_{pos}PEpos​, so relative offsets are in principle easy to learn.

RoPE (rotary position embedding). Group the dkd_kdk​ coordinates of a query or key into pairs, and rotate pair iii by angle mθim\theta_imθi​ where mmm is the token position and θi=10000−2i/dk\theta_i = 10000^{-2i/d_k}θi​=10000−2i/dk​ (the base is a hyperparameter). Let RmR_mRm​ be the block-diagonal rotation. Because rotations compose, Rm⊤Rn=Rn−mR_m^\top R_n = R_{n-m}Rm⊤​Rn​=Rn−m​, so

(Rmq)⊤(Rnk)=q⊤Rn−m k.(R_m q)^\top (R_n k) = q^\top R_{n-m}\, k.(Rm​q)⊤(Rn​k)=q⊤Rn−m​k.

The attention score depends on the content of q,kq, kq,k and only on the relative offset n−mn-mn−m, even though each vector is rotated using its absolute position. RoPE adds no learned parameters, and long-context extensions commonly rescale the angles or base (position interpolation and related methods), typically followed by some fine-tuning.

ALiBi. Add a bias to the score between query iii and key j≤ij\le ij≤i:

scoreij=qi⊤kjdk−sh (i−j)\text{score}_{ij} = \frac{q_i^\top k_j}{\sqrt{d_k}} - s_h\,(i-j)scoreij​=dk​​qi⊤​kj​​−sh​(i−j)

where sh>0s_h>0sh​>0 is a fixed, head-specific slope (a geometric sequence across heads). Distant tokens are down-weighted linearly. The authors report better extrapolation to sequence lengths longer than seen in training than sinusoidal embeddings; how well any scheme extrapolates depends on the model and the task.

Interview angle

The crisp contrast: absolute schemes tell each token where it is; RoPE and ALiBi make the score between two tokens depend on their distance. Also note that in a causal decoder, positional information can in principle be partially inferred from the mask itself, which is one reason some models work without explicit encodings; this is a nuance, not the standard answer.

#Encoder, decoder, encoder-decoder

Family Attention pattern Training objective (typical) Examples Best suited for
Encoder-only Bidirectional: every token sees all tokens Masked language modeling BERT Classification, embeddings, tagging, retrieval encoders
Decoder-only Causal: token iii sees only positions ≤i\le i≤i Next-token prediction GPT-family models Open-ended generation, and in practice most general-purpose LLMs
Encoder-decoder Encoder bidirectional; decoder causal plus cross-attention to encoder outputs Span corruption, seq2seq T5, original transformer Translation, summarization, tasks with a distinct input and output

In cross-attention, queries come from the decoder state and keys/values from the encoder output, so each output token can look at the whole input.

Why decoder-only dominates generation today is partly empirical and partly practical: one objective (next token) covers pretraining, a single stack is simpler to scale, and in-context prompting makes the prompt/response split unnecessary. Encoder-decoder models remain competitive on many seq2seq tasks; the claim is about prevailing practice, not a proof of superiority.

#Causal masking

For autoregressive modeling, position iii must not see tokens after iii, otherwise the model could copy the label it is supposed to predict. The mask is added to the score matrix before the softmax:

Mij={0j≤i−∞j>i,softmax ⁣(QK⊤dk+M)M_{ij} = \begin{cases} 0 & j \le i\\ -\infty & j > i\end{cases},\qquad \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}} + M\right)Mij​={0−∞​j≤ij>i​,softmax(dk​​QK⊤​+M)

The −∞-\infty−∞ entries become zero probability. Thanks to the mask, all nnn positions can be trained in parallel in one forward pass, each predicting its own next token (teacher forcing). At inference, tokens are produced one at a time because each output is the input to the next step.

Padding mask vs causal mask

They are different. The causal mask hides the future; the padding mask hides pad tokens in batched, variable-length sequences. Decoder training uses both.

#The transformer block

A standard block applies attention then an FFN, each with a residual connection and normalization.

#Residual connections and LayerNorm

A residual connection computes x+Sublayer(x)x + \text{Sublayer}(x)x+Sublayer(x). It gives gradients a direct path through depth and lets each sublayer learn a correction rather than a full transformation. LayerNorm normalizes each token's feature vector across the feature dimension (not across the batch):

LN(x)=γ⊙x−μσ2+ϵ+β,\text{LN}(x) = \gamma \odot \frac{x-\mu}{\sqrt{\sigma^2+\epsilon}} + \beta,LN(x)=γ⊙σ2+ϵ​x−μ​+β,

where μ,σ2\mu,\sigma^2μ,σ2 are the mean and variance over the dmodeld_{model}dmodel​ features of that token. It does not depend on batch size or on other tokens, which suits variable-length sequences. Many recent LLMs use RMSNorm, which drops the mean subtraction and bias and rescales by the root mean square; it is cheaper, and reported quality is generally comparable.

Post-norm Pre-norm
Formula xl+1=LN(xl+F(xl))x_{l+1} = \text{LN}\big(x_l + F(x_l)\big)xl+1​=LN(xl​+F(xl​)) xl+1=xl+F(LN(xl))x_{l+1} = x_l + F\big(\text{LN}(x_l)\big)xl+1​=xl​+F(LN(xl​))
Residual path Passes through a LayerNorm each layer Stays an unnormalized identity path
Training stability Needs learning-rate warmup; harder to train at depth Generally more stable, often trains with less tuning
Trade-off Some results suggest slightly better final quality when it does train Hidden-state magnitude can grow with depth; often a final norm is added before the output

The original transformer used post-norm; most large recent models use pre-norm (or variants), chiefly for stability. This is a tendency across published models, and exceptions and hybrids exist.

#Feed-forward network (FFN)

Applied to each position independently with the same weights:

FFN(x)=W2 σ(W1x+b1)+b2,W1∈Rdff×dmodel\text{FFN}(x) = W_2\,\sigma(W_1 x + b_1) + b_2,\qquad W_1\in\mathbb{R}^{d_{ff}\times d_{model}}FFN(x)=W2​σ(W1​x+b1​)+b2​,W1​∈Rdff​×dmodel​

with dffd_{ff}dff​ commonly 4 dmodel4\,d_{model}4dmodel​. Attention moves information between tokens; the FFN processes information within each token and holds a large share of parameters: 2 dmodeldff=8 dmodel22\,d_{model}d_{ff} = 8\,d_{model}^22dmodel​dff​=8dmodel2​ versus 4 dmodel24\,d_{model}^24dmodel2​ for attention, so roughly two thirds of a standard block's parameters. Some analyses interpret FFN layers as key-value memories storing factual associations; treat that as an informative hypothesis, not settled mechanism. Modern models often use gated variants (for example SwiGLU), with dffd_{ff}dff​ adjusted to keep parameter count similar. Mixture-of-experts replaces the single FFN with many, routing each token to a few.

#Complexity: why attention is O(n2)O(n^2)O(n2)

Component Time per layer Memory notes
Q, K, V, O projections O(n dmodel2)O(n\,d_{model}^2)O(ndmodel2​) Weights 4dmodel24d_{model}^24dmodel2​
Score matrix QK⊤QK^\topQK⊤ and weighted sum O(n2dmodel)O(n^2 d_{model})O(n2dmodel​) Naively stores n×nn\times nn×n scores per head
FFN O(n dmodel dff)=O(n dmodel2)O(n\,d_{model}\,d_{ff}) = O(n\,d_{model}^2)O(ndmodel​dff​)=O(ndmodel2​) Weights ≈8dmodel2\approx 8 d_{model}^2≈8dmodel2​

Which term dominates depends on nnn versus dmodeld_{model}dmodel​: attention's n2dmodeln^2 d_{model}n2dmodel​ term is larger than the linear terms roughly when nnn exceeds a small multiple of dmodeld_{model}dmodel​. For moderate sequence lengths, the FFN and projections can dominate FLOPs, while the n×nn\times nn×n score memory is the bottleneck sooner. Doubling the context roughly quadruples the attention-score work.

Mitigations: sparse or local attention patterns, linear-attention approximations, low-rank methods, state-space hybrids, and IO-aware exact kernels (below). Approximate methods trade accuracy for cost, and exact attention with efficient kernels is the most common choice in practice.

#KV cache

In autoregressive generation, the keys and values of past tokens do not change when a new token is added (in a causal model, earlier positions never attend to later ones). So the model stores each layer's KKK and VVV for all previous tokens and, at each step, computes only the new token's q,k,vq, k, vq,k,v, appends k,vk, vk,v to the cache, and attends over the cached entries.

  • Saves: recomputing the whole prefix each step. Per-step attention cost becomes O(n d)O(n\,d)O(nd) per layer instead of reprocessing O(n2d)O(n^2 d)O(n2d).
  • Costs: memory. Per token the cache holds

2×L×nkv×dhead×bytes per value2 \times L \times n_{kv} \times d_{head} \times \text{bytes per value}2×L×nkv​×dhead​×bytes per value

where nkvn_{kv}nkv​ is the number of KV heads. Worked example (hypothetical): L=32L=32L=32, nkv=32n_{kv}=32nkv​=32, dhead=128d_{head}=128dhead​=128, 16-bit values give 2⋅32⋅32⋅128⋅2=524,2882\cdot32\cdot32\cdot128\cdot2 = 524{,}2882⋅32⋅32⋅128⋅2=524,288 bytes, i.e. 0.5 MiB per token. A 4,096-token sequence needs about 2 GiB, per sequence in the batch. At large batch sizes and long contexts the cache can exceed the model weights.

Interview angle

Distinguish prefill (process the whole prompt in parallel; compute-bound) from decode (one token at a time, reading weights and the cache from memory each step; typically memory-bandwidth-bound). The KV cache is the reason decode is feasible, and also why long contexts and large batches are memory-limited.

#FlashAttention: the idea

Standard attention writes the n×nn\times nn×n score and probability matrices to GPU high-bandwidth memory (HBM) and reads them back. On modern GPUs, the attention operation is often limited by this memory traffic rather than by arithmetic. FlashAttention computes exact attention while avoiding materializing the full matrix in HBM:

  1. Tiling: split Q,K,VQ, K, VQ,K,V into blocks that fit in fast on-chip SRAM, and process one block pair at a time.
  2. Online softmax: maintain a running row-wise maximum and normalizer, so the softmax can be computed incrementally across key blocks without seeing the whole row.
  3. Fusion and recomputation: fuse the steps into one kernel, and in the backward pass recompute scores from the saved normalizers instead of storing them.

Results: memory for attention drops from O(n2)O(n^2)O(n2) to O(n)O(n)O(n) extra, wall-clock time improves because of fewer HBM reads and writes, and the arithmetic is still O(n2)O(n^2)O(n2) and the output is identical up to floating-point effects. It is an IO-aware implementation, not an approximation.

#Reducing KV cost: MQA and GQA

Variant Query heads KV heads Effect
MHA hhh hhh Baseline quality, largest cache
MQA (multi-query) hhh 1 Cache shrinks by about h×h\timesh×; some quality loss can occur
GQA (grouped-query) hhh ggg with 1<g<h1<g<h1<g<h Cache shrinks by about h/gh/gh/g; quality typically close to MHA

In GQA, each group of h/gh/gh/g query heads shares one key/value head. Example: 32 query heads and 8 KV heads gives a 4x smaller KV cache and lower memory traffic per decode step. Models can be converted from MHA to GQA by merging KV heads and briefly continuing training ("uptraining"). The attention-parameter count also falls slightly, since WK,WVW_K, W_VWK​,WV​ are smaller.

#Why transformers beat RNNs

Aspect RNN / LSTM Transformer
Parallelism over the sequence (training) Sequential: step ttt needs step t−1t-1t−1 All positions processed in parallel; suits GPUs
Path between distant tokens O(n)O(n)O(n) steps; gradients must survive many multiplications O(1)O(1)O(1): any token attends directly to any other
Context representation Fixed-size hidden state (compressed) Full set of past keys/values (uncompressed)
Cost per layer O(n d2)O(n\,d^2)O(nd2) O(n2d+nd2)O(n^2 d + n d^2)O(n2d+nd2)
Inference memory Constant in nnn KV cache grows linearly in nnn
Scaling behavior Harder to scale in practice Scaled to very large models and datasets

The main reasons transformers took over: training parallelism (lets hardware be used efficiently on huge datasets) and short paths for long-range dependencies. RNNs retain advantages in constant-memory, constant-time-per-token inference, which motivates recent recurrent and state-space architectures that aim to recover parallel training with RNN-like inference. Claims that transformers are strictly better are too strong; the claim is that, at current scales and hardware, they have given the best quality per training cost on most language tasks.

Go deeper (optional)

Attention can be viewed as a kernel-weighted average (a soft nearest-neighbor lookup over keys), and with softmax removed or replaced by a feature map, it can be rewritten as a recurrence, which is the link to linear-attention and state-space models. Separately, "attention sinks" (some models put large weight on the first token) is an observed phenomenon relevant to streaming and sliding-window inference.

#Common pitfalls

  • Confusing the two masks (causal vs padding).
  • Saying attention is O(n2)O(n^2)O(n2) in parameters. The quadratic is in sequence length for time and score memory; parameter count does not depend on nnn.
  • Saying FlashAttention is an approximation. It is exact; it changes memory access patterns.
  • Forgetting the KV cache is per sequence. Serving many concurrent requests multiplies it.
  • Treating embeddings as static. The input embedding is context-free; context-dependent representations appear only after attention layers.
Rapid fire

Tokens →\to→ embeddings →\to→ LLL blocks of (attention, FFN) with residuals and norms →\to→ output logits over the vocabulary. Attention: softmax(QK⊤/dk)V\text{softmax}(QK^\top/\sqrt{d_k})Vsoftmax(QK⊤/dk​​)V, score matrix n×nn\times nn×n. Scaling counters variance growth dkd_kdk​ and softmax saturation. Position: sinusoidal added to inputs; RoPE rotates Q,KQ,KQ,K so scores depend on relative offset; ALiBi biases scores by distance. Causal mask enables parallel training of next-token prediction. Pre-norm is typically more stable. KV cache trades memory for compute; GQA/MQA shrink it; FlashAttention is exact and IO-aware.

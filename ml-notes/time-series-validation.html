Time-Series Validation & Backtesting

Say it in 30s: Never random K-fold on time series — it leaks the future. Use rolling-origin evaluation: train on data up to time ttt, forecast horizon hhh, score, advance ttt, repeat. Choose expanding window (all history) or sliding window (recent window only) based on drift. Features must use only information available at prediction time; match production horizon hhh in the backtest or metrics lie.

Key points

  • Expanding window: grows training set — stable if the process is stationary enough.
  • Sliding window: fixed length — better when old regime is irrelevant.
  • Add a gap (embargo) if features use long lags to prevent peeking.
  • Always benchmark vs naive (last value, seasonal naive); report MASE or WAPE for scale-free comparison.

Common follow-ups / traps

  • "Can I use cross-validation?" → Only time-series CV (purged, embargoed) — see Cross-Validation for generic pitfalls, not the default splitter.
  • "Why did offline beat naive but prod failed?" → Wrong hhh, leakage in features, or train/serve skew on live covariates.

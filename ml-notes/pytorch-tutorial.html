PyTorch Tutorial

From a tensor to a saved, evaluated model: one complete, runnable training workflow.

For the theory of how weights get updated, see PyTorch: Weights, Gradients & Backprop. This page is the practical counterpart.

#1. Tensors

A tensor is an n-dimensional array that can live on a GPU and can track gradients.

import torch
torch.manual_seed(0)

a = torch.tensor([[1., 2.], [3., 4.]])
b = torch.randn(2, 2)
a.shape, a.dtype, a.device           # torch.Size([2, 2]), torch.float32, cpu
a @ b                                # matrix multiply (not a * b, which is elementwise)
a.sum(dim=0)                         # reduce over rows → shape [2]
a[:, 0]                              # indexing works like NumPy

Shapes cause most bugs. Print x.shape often. Convention: batch dimension first, [B, features].

#2. Autograd

Mark a tensor requires_grad=True and PyTorch records operations so it can differentiate them.

x = torch.randn(3, 4, requires_grad=True)
y = (x ** 2).sum()
y.backward()                          # computes dy/dx
torch.allclose(x.grad, 2 * x)         # True

Gradients accumulate into .grad on every backward(), which is why training loops call zero_grad() each step.

#3. Data: Dataset and DataLoader

from torch.utils.data import TensorDataset, DataLoader, random_split

N = 2000
X = torch.randn(N, 10)
w = torch.randn(10)
y = ((X @ w + 0.5 * torch.randn(N)) > 0).float()     # binary labels as float for BCE

ds = TensorDataset(X, y)
train_ds, val_ds = random_split(ds, [1600, 400], generator=torch.Generator().manual_seed(0))
train_loader = DataLoader(train_ds, batch_size=64, shuffle=True)    # shuffle only for training
val_loader = DataLoader(val_ds, batch_size=256)

For real data, subclass Dataset and implement __len__ and __getitem__. DataLoader handles batching, shuffling and (with num_workers) parallel loading.

#4. Define a model

import torch.nn as nn

class MLP(nn.Module):
    def __init__(self, d_in, hidden=32):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(d_in, hidden), nn.ReLU(), nn.Dropout(0.1),
            nn.Linear(hidden, 1),
        )

    def forward(self, x):
        return self.net(x).squeeze(-1)        # raw logits, shape [B]

Return logits, not probabilities. The loss below applies the sigmoid internally in a numerically stable way.

#5. Loss, optimizer, device

device = torch.device("cuda" if torch.cuda.is_available()
                      else "mps" if torch.backends.mps.is_available() else "cpu")

model = MLP(10).to(device)
loss_fn = nn.BCEWithLogitsLoss()
opt = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=1e-2)
sched = torch.optim.lr_scheduler.CosineAnnealingLR(opt, T_max=20)

Data and model must be on the same device. Move each batch with .to(device).

#6. The training loop

best = float("inf")
for epoch in range(20):
    model.train()                                   # enables dropout, batchnorm training mode
    for xb, yb in train_loader:
        xb, yb = xb.to(device), yb.to(device)
        opt.zero_grad(set_to_none=True)             # 1. clear old gradients
        loss = loss_fn(model(xb), yb)               # 2. forward + loss
        loss.backward()                             # 3. backprop
        nn.utils.clip_grad_norm_(model.parameters(), 1.0)   # optional stability
        opt.step()                                  # 4. update weights
    sched.step()                                    # once per epoch for this scheduler

    model.eval()                                    # disables dropout
    total, correct, n = 0.0, 0, 0
    with torch.no_grad():                           # no graph, less memory
        for xb, yb in val_loader:
            xb, yb = xb.to(device), yb.to(device)
            logits = model(xb)
            total += loss_fn(logits, yb).item() * len(yb)
            correct += ((logits > 0).float() == yb).sum().item()
            n += len(yb)
    val_loss = total / n
    if val_loss < best:                             # keep the best checkpoint
        best = val_loss
        torch.save(model.state_dict(), "best.pt")
    print(epoch, round(val_loss, 4), round(correct / n, 4))

The four-line core (zero_grad, forward/loss, backward, step) is the same for every PyTorch model, from this MLP to a transformer.

#7. Save and load

model2 = MLP(10)
model2.load_state_dict(torch.load("best.pt", map_location="cpu", weights_only=True))
model2.eval()

Save the state_dict (weights only), not the whole model object. It survives code refactors and weights_only=True avoids loading arbitrary pickled code.

#8. Predict

model2.eval()
with torch.no_grad():
    probs = torch.sigmoid(model2(X[:5]))

#Debugging checklist

  1. Overfit one small batch first. If loss will not go near zero on 32 examples, the bug is in the code, not the data.
  2. Loss is NaN → learning rate too high, bad input values, or log(0); try gradient clipping and a smaller lr.
  3. Loss does not move → forgot opt.step(), wrong zero_grad placement, or parameters not passed to the optimizer.
  4. Validation much worse than train → regularize (dropout, weight decay), get more data, stop earlier.
  5. Results differ between runs → set torch.manual_seed; some GPU ops stay non-deterministic.

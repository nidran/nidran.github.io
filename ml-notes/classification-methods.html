Classical Models · chapter · 15 min read

Classification Methods

Classification — predicting a discrete label — is the single most common framing you'll be asked to reason about, and interviewers use it to probe whether you understand why one model beats another on a given dataset, not just how to call .fit(). We line every major classifier up side by side, split them into the two families that organize the whole field, then walk each one with its assumptions, strengths, and the questions it tends to attract.

What you'll be able to say after this chapter
  • Place any classifier in the generative vs discriminative split and say what it learns.
  • Derive logistic regression from the log-odds and explain why it's the default baseline.
  • Explain why Naive Bayes works despite a "naive" assumption that's almost always false.
  • Contrast bagging vs boosting in one sentence and say which fights bias vs variance.
  • Pick a classifier from the shape of the data: size, dimensionality, linearity, interpretability.

#The Master Table — Every Classifier Side by Side

Before any single method, hold the landscape in your head. The classifiers you'll be asked about differ along a few axes that actually predict their behavior: what they learn, whether the boundary is linear, how they scale, and how interpretable they are.

Model Family Boundary Strengths Watch out for
Logistic regression Discriminative Linear Usually well-calibrated probabilities, interpretable, fast Underfits nonlinear data
Naive Bayes Generative Linear in log-space (multinomial/Bernoulli; Gaussian NB can be quadratic) Tiny data, text, very fast Independence assumption, poor calibration
k-NN Discriminative (lazy) Nonlinear No training, simple Slow at predict, curse of dimensionality
SVM Discriminative Linear or kernel Strong in high-dim, margin-based Slow on big data, no native probabilities
Decision tree Discriminative Axis-aligned Interpretable, handles mixed types Overfits, unstable
Random forest Discriminative (bagging) Nonlinear Robust, low tuning, strong default Larger, less interpretable
Gradient boosting Discriminative (boosting) Nonlinear Often best on tabular Tuning-sensitive, slower to train
Neural network Discriminative Arbitrary Crushes vision/text/audio Data-hungry, opaque, tuning
Memory hook

Two questions sort almost any classifier: does it model the data (generative) or just the boundary (discriminative)? and is the boundary a straight line or can it bend? Everything else is a footnote on cost and interpretability.

Interview angle

"Walk me through which classifier you'd try." Don't recite — reason from the data. The senior move: name a fast linear baseline (logistic regression), then a strong nonlinear default (gradient-boosted trees for tabular, a neural net for perceptual data), and justify each by the data's structure. Jumping straight to "XGBoost" without a baseline reads as junior.

#Two Families: Generative vs Discriminative

This split organizes the entire chapter, so it's worth one clean restatement. A discriminative model learns the boundary directly — p(y∣x)p(y \mid x)p(y∣x), or just where the line goes. A generative model learns how each class produces data — p(x∣y)p(x \mid y)p(x∣y) and p(y)p(y)p(y) — then flips it with Bayes' rule to classify.

Discriminative Generative
Learns p(y∣x)p(y \mid x)p(y∣x) — the boundary p(x,y)=p(x∣y) p(y)p(x, y) = p(x \mid y)\,p(y)p(x,y)=p(x∣y)p(y) — the full story
Classifies by Which side of the line? Which class most likely generated this xxx?
Can sample / detect outliers? No Yes
Data appetite Wants more data, hits lower error Works on small data if assumptions hold
Examples Logistic regression, SVM, trees, NN Naive Bayes, GMM, LDA, HMM

The practical takeaway is the Ng–Jordan result from Fundamentals: a generative model reaches its error floor with fewer samples but that floor is higher; the matching discriminative model is slower to converge but ends up more accurate with enough data. So generative shines in the small-data regime, discriminative in the large-data regime.

Memory hook

Discriminative asks "which side?" Generative asks "who made this?" — it learns each class's recipe and picks the most plausible cook.

#Logistic Regression — The Must-Know Baseline

Despite the name, logistic regression is a classifier. It's the single most important model to be able to derive from scratch, because nearly every interview that touches classification touches it.

The setup: a linear model produces a score z=w⊤x+bz = w^\top x + bz=w⊤x+b that lives anywhere on the real line, but a probability has to sit in [0,1][0, 1][0,1]. The sigmoid squashes it: σ(z)=11+e−z\sigma(z) = \dfrac{1}{1 + e^{-z}}σ(z)=1+e−z1​. Read backwards, this says the model is linear in the log-odds:

log⁡p1−p=w⊤x+b\log\frac{p}{1 - p} = w^\top x + blog1−pp​=w⊤x+b

That single fact is the heart of the method — a one-unit change in a feature shifts the log-odds by its weight.

It's trained by minimizing cross-entropy (log-loss), not squared error. The reason matters and gets asked: cross-entropy is the negative log-likelihood under a Bernoulli model, it's convex in the weights (so any local optimum is global; with separable data the weights diverge unless regularized), and it punishes confident wrong predictions hard. Squared error on a sigmoid is non-convex and produces vanishing gradients when the model is confidently wrong — exactly when you most need a signal.

Property Logistic regression Why it matters
Output Usually well-calibrated probability Threshold it for any precision/recall tradeoff
Boundary Linear in features Add interactions/polynomials for curves
Loss Cross-entropy (convex) Global optimum, clean gradients
Regularization L1 (sparse) or L2 (shrink) Controls overfitting, L1 selects features
Memory hook

Logistic regression is linear regression on the log-odds, then squashed by a sigmoid. "Linear in log-odds, probability out."

Interview angle

Three near-certain questions: (1) Why sigmoid? — to map a real-valued score to [0,1][0,1][0,1] and make it linear in log-odds. (2) Why cross-entropy not MSE? — convexity + non-vanishing gradients + it's the Bernoulli MLE. (3) Is it linear? — the boundary is linear in features, even though the sigmoid is nonlinear. Getting (3) right separates people who memorized from people who understand.

Go deeper (optional)

For multiclass, logistic regression generalizes to softmax (multinomial) regression: one weight vector per class, normalized to a distribution. Softmax + cross-entropy is exactly the output layer of most neural-net classifiers — so "what's the last layer of a classifier net?" is the same idea you already know.

#Naive Bayes — Fast and Great for Text

Naive Bayes is the canonical generative classifier and a perennial interview favorite because its central paradox is so clean: it rests on an assumption that is almost always false, and it works anyway.

It applies Bayes' rule — p(y∣x)∝p(y) p(x∣y)p(y \mid x) \propto p(y)\,p(x \mid y)p(y∣x)∝p(y)p(x∣y) — and makes the "naive" assumption that all features are conditionally independent given the class. That lets it factor p(x∣y)p(x \mid y)p(x∣y) into a product of per-feature terms, which is why it trains in a single pass and handles tens of thousands of features (every word in a vocabulary) effortlessly.

The assumption is obviously wrong — in text, "New" and "York" are not independent. But Naive Bayes only needs the correct class to get the highest score, not accurate probabilities. The dependencies often distort all classes' scores in the same direction, so the argmax survives even when the probabilities themselves are badly miscalibrated. That's the resolution to the paradox, and the answer interviewers want.

Variant Use on Models each feature as
Multinomial NB Word counts (text) Count from a multinomial
Bernoulli NB Binary presence/absence 0/1 per feature
Gaussian NB Continuous features A normal distribution

Two practical notes that come up: Laplace (add-one) smoothing is essential — without it, a single unseen word gives p=0p = 0p=0 and zeroes out the whole product. And NB probabilities are poorly calibrated (pushed toward 0 or 1 by the independence assumption), so trust its ranking and labels, not its confidence numbers.

Memory hook

Naive Bayes assumes every feature votes independently. The assumption is a lie, but the winner of the vote is usually still right — good classification, bad probabilities.

Interview angle

"Why does Naive Bayes work if the independence assumption is false?" The crisp answer: it only needs the right class to win the argmax, not calibrated probabilities; the errors are often shared across classes and cancel at the decision. Bonus points for mentioning Laplace smoothing and that it's a strong, near-free baseline for text.

#k-NN and SVM — Distance vs Margin

These two are usually taught together because they represent two opposite instincts about what makes a good boundary: be like your neighbors versus stay as far from everyone as possible.

k-Nearest Neighbors is the laziest model there is — it does no training, just stores the data. To classify a point, it finds the kkk closest stored examples and takes a majority vote. Small kkk means a jagged, low-bias/high-variance boundary; large kkk smooths it out (higher bias, lower variance). Its weaknesses are exactly its design: prediction is slow (you compare against everything), it's memory-heavy, and it dies in high dimensions because distances become meaningless — the curse of dimensionality. It also demands feature scaling, since raw-scale features dominate the distance.

Support Vector Machines take the opposite stance: among all lines that separate the classes, pick the one with the widest margin — the largest gap to the nearest points (the support vectors). A wide margin is a built-in regularizer, which is why SVMs are strong in high-dimensional spaces like text. The kernel trick lets them draw nonlinear boundaries by implicitly mapping data to a higher-dimensional space without ever computing the coordinates — the RBF kernel is the common default.

k-NN SVM
Training None (lazy) Solve a convex optimization
Idea Vote of nearest neighbors Maximize the margin
Boundary Flexible, local Linear, or kernel for nonlinear
Scales to big data? Predict is slow Training slow, predict fast
Key knobs kkk, distance metric, scaling CCC (margin softness), kernel
Memory hook

k-NN: "tell me who your neighbors are." SVM: "draw the boundary down the widest empty street." One is lazy and local; the other is a global optimizer obsessed with the margin.

Interview angle

For k-NN expect "what happens as kkk grows?" (bias up, variance down) and "why does it fail in high dimensions?" (distances concentrate, neighbors stop being meaningful). For SVM expect "what's a support vector?" (a point on or inside the margin that defines the boundary) and "what does the kernel trick buy you?" (nonlinear boundaries without explicit high-dimensional features).

Go deeper (optional)

The SVM CCC parameter is the margin-softness knob: small CCC = wide, soft margin tolerating misclassifications (more bias, less variance); large CCC = narrow, hard margin fitting the training data tightly (less bias, more variance). It's the same bias-variance dial in margin clothing.

#Trees, Forests, Boosting — Bagging vs Boosting

Tree-based models dominate tabular data, and the progression from a single tree to forests to boosting is one of the most testable arcs in ML.

A decision tree splits the feature space with a sequence of yes/no questions, choosing each split to most reduce impurity (Gini or entropy for classification). It's wonderfully interpretable and handles mixed feature types with no scaling — but a single deep tree overfits badly and is unstable: change a few points and the whole tree can rearrange. That instability is the opening for ensembles.

The two ways to combine many trees are the central contrast of this section.

Bagging (Random Forest) Boosting (GBM / XGBoost)
Trees are trained In parallel, independently Sequentially, each fixing the last
Each tree sees A bootstrap sample (+ random feature subset at each split) The residual errors so far
Primarily reduces Variance Bias
Failure mode Slightly weaker than tuned boosting Overfits if over-trained / under-regularized
Tuning burden Low (strong out of the box) Higher (learning rate, depth, rounds)

Random forests grow many deep, decorrelated trees on bootstrap samples with random feature subsets, then average them. Averaging many high-variance, low-bias trees cancels the variance — a robust, low-maintenance default. Gradient boosting instead builds shallow trees one at a time, each trained on the previous ensemble's errors, steadily driving down bias. Tuned well (XGBoost, LightGBM, CatBoost), boosting is usually the top performer on heterogeneous tabular data.

Memory hook

Bagging = a committee voting in parallel to cancel each other's mistakes (kills variance). Boosting = a relay team, each runner covering the last one's shortfall (kills bias).

Interview angle

The bagging-vs-boosting contrast is asked constantly. Nail the one-liner: bagging trains independent trees in parallel to reduce variance; boosting trains dependent trees sequentially on residuals to reduce bias. Follow-ups: "why are random-forest trees deep but boosting trees shallow?" (deep = low-bias high-variance, perfect for averaging; shallow = weak learners boosting corrects gradually) and "which overfits more easily?" (boosting, since it keeps fitting residuals).

#Ensembles in Full

Zooming out, the ensembles above are three instances of one principle: combine many models so their errors cancel. Worth knowing all the named patterns.

Method How it combines Mainly helps
Bagging Parallel models on bootstrap samples, then average/vote Variance
Boosting Sequential models on residuals Bias
Stacking A meta-model learns to blend base models' predictions Both (if base models are diverse)
Voting Hard (majority) or soft (average probabilities) Variance

The condition for an ensemble to help is diversity: the base models must make different errors. Averaging ten copies of the same model gains nothing. This is why random forests inject randomness (bootstrap rows + random feature subsets) — to decorrelate the trees so their mistakes don't line up.

Memory hook

An ensemble only helps if its members are wrong in different ways. Diversity is the whole trick — identical experts add nothing; disagreeing experts cancel each other's blind spots.

Go deeper (optional)

Stacking/blending of diverse models wins many Kaggle competitions: train diverse base models (trees, linear, nets), then a meta-learner on their out-of-fold predictions. The subtlety is leakage — the meta-model must be trained on held-out base predictions, or it learns from data the base models already saw.

#Which Classifier When

The payoff of the chapter: matching a model to the data in front of you. This is the decision interviewers actually want to see you make.

Situation Reach for
Need a fast, interpretable baseline Logistic regression
Text / very high-dimensional sparse data Naive Bayes or linear SVM
Tabular data, want top accuracy Gradient boosting (XGBoost/LightGBM)
Tabular data, want robust + low tuning Random forest
Images, audio, language Neural network
Small data, low dimensions, nonlinear k-NN or SVM (RBF)
Need calibrated probabilities Logistic regression (usually well calibrated), or calibrate afterward
Need to explain every prediction Single decision tree or logistic regression

The meta-strategy: always start with a simple baseline (logistic regression or a shallow tree), measure it honestly, then escalate to a stronger model only if the baseline leaves accuracy on the table. The baseline also catches leakage — a too-good baseline score is a red flag, not a victory.

Interview angle

"You have a tabular dataset with 50k rows and mixed feature types — what do you use?" Strong answer: a logistic-regression baseline for a reference point and calibration, then gradient-boosted trees as the likely winner, justified by their fit to heterogeneous tabular data and their handling of nonlinearities and interactions without manual feature engineering. Then mention you'd validate the choice empirically — No Free Lunch.

#Cross-Cutting Skills (Asked of Senior Candidates)

Beyond naming models, senior interviews probe a few skills that cut across all classifiers.

Handling class imbalance. When one class is rare (fraud, disease), accuracy is useless and most classifiers drift toward the majority. Levers: resample (SMOTE / oversample minority, undersample majority), reweight the loss to penalize minority errors more, and — most importantly — change the metric to precision/recall, F1, or PR-AUC instead of accuracy.

Multiclass from binary models. Models like SVM are natively binary. One-vs-Rest trains one classifier per class against all others (kkk classifiers); One-vs-One trains one per pair (k(k−1)/2k(k-1)/2k(k−1)/2 classifiers, each on less data). Logistic regression and trees handle multiclass natively via softmax / multi-way splits.

Calibration. A model can rank well but report dishonest probabilities (Naive Bayes, SVMs, deep nets often do). If you need the number 0.7 to mean "70% of the time," calibrate with Platt scaling or isotonic regression on held-out data (see Model Evaluation & Validation).

Memory hook

Three senior reflexes: imbalanced data → change the metric first, resampling/reweighting second. Binary-only model → wrap it in One-vs-Rest. Probabilities you'll act on → calibrate them.

Rapid fire — Classification
  • Two families: discriminative learns the boundary p(y∣x)p(y\mid x)p(y∣x); generative learns p(x,y)p(x,y)p(x,y) and can sample. Generative wins small-data, discriminative wins large-data.
  • Logistic regression: linear in log-odds, sigmoid out, trained with convex cross-entropy. The boundary is linear; use it as the baseline.
  • Naive Bayes: assumes conditional independence (false) but wins the argmax anyway; great for text; use Laplace smoothing; poorly calibrated.
  • k-NN: lazy, local, dies in high dimensions, needs scaling. SVM: max-margin, strong in high-dim, kernel trick for nonlinearity.
  • Trees overfit and are unstable. Bagging (random forest) = parallel trees killing variance; boosting (XGBoost) = sequential trees killing bias.
  • Ensembles need diverse base models (wrong in different ways) to help.
  • Pick by data: logistic baseline → boosting for tabular, NN for perceptual, NB/linear-SVM for text.
  • Imbalance → change the metric (PR-AUC, F1) before resampling/reweighting.

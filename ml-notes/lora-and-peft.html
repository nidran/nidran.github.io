LoRA & Parameter-Efficient Fine-Tuning

Say it in 30s: Full fine-tuning updates every weight; PEFT updates a tiny side path instead. LoRA freezes the pretrained matrix WWW and learns a low-rank update W′=W+αrBAW' = W + \frac{\alpha}{r}BAW′=W+rα​BA, with B∈Rdout×rB \in \mathbb{R}^{d_{\text{out}} \times r}B∈Rdout​×r, A∈Rr×dinA \in \mathbb{R}^{r \times d_{\text{in}}}A∈Rr×din​—so you train r(din+dout)r(d_{\text{in}}+d_{\text{out}})r(din​+dout​) parameters per adapted layer instead of dindoutd_{\text{in}} d_{\text{out}}din​dout​. Typical targets: attention WQ,WK,WV,WOW_Q, W_K, W_V, W_OWQ​,WK​,WV​,WO​ (sometimes FFN). QLoRA adds 4-bit quantized base weights plus LoRA adapters in higher precision.

Key points

  • Rank rrr trades capacity for cost: r=8r=8r=8–646464 is common; α\alphaα scales the effective learning rate of the adapter (often α=r\alpha = rα=r or 2r2r2r).
  • At d=4096d=4096d=4096, r=16r=16r=16, one square matrix trains 2dr=131,0722dr = 131{,}0722dr=131,072 params instead of 16.816.816.8M (≈0.8%)—four attention matrices per layer ≈ 5.2×1055.2\times 10^55.2×105 trainable vs 676767M frozen per layer.
  • Alternatives: adapters (bottleneck FFN inside each block), prefix / prompt tuning (learn soft prompt vectors, zero change to weights).
  • Merge adapters into WWW at inference for zero latency overhead; keep separate for multi-task swapping.

Common follow-ups / traps

  • "Why low-rank works?" → instruction shifts often lie in a low-dimensional subspace; you're not re-learning the whole representation.
  • "LoRA vs full FT?" → LoRA when data is modest and you must preserve base capabilities; full FT when the task rewires behavior heavily (watch catastrophic forgetting).
  • "Which matrices?" → all four attention projections give the best quality/$; FFN LoRA helps on hard domain adaptation.

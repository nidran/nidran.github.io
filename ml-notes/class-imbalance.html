Class Imbalance

Say it in 30s: When positives are rare (fraud, disease, clicks), accuracy is useless and default 0.5 thresholds waste recall. Responses: class weights or resampling (undersample majority, oversample minority — SMOTE synthesizes borderline positives but can blur decision boundaries if overused), threshold tuning on validation, focal loss for hard examples in deep nets, and metrics that ignore the TN flood: PR-AUC, precision/recall, or cost-sensitive scores. Always align the metric with the cost of a miss vs a false alarm.

Key points

  • Lower threshold → higher recall, lower precision; pick the operating point by business cost, not default 0.5.
  • Resampling changes the training distribution — recalibrate probabilities if you care about calibrated scores.
  • Report PR curve, not ROC alone, when prevalence is skewed (ROC-AUC vs PR-AUC).

Focal loss down-weights easy examples: Lfocal=−(1−pt)γlog⁡ptL_{\mathrm{focal}} = -(1-p_t)^\gamma \log p_tLfocal​=−(1−pt​)γlogpt​, ptp_tpt​ = probability assigned to the true class. At γ=2\gamma=2γ=2: pt=0.9⇒L≈0.001p_t=0.9 \Rightarrow L \approx 0.001pt​=0.9⇒L≈0.001; pt=0.1⇒L≈1.87p_t=0.1 \Rightarrow L \approx 1.87pt​=0.1⇒L≈1.87 — hard mistakes dominate gradients.

Prior / threshold shift: if training downsampled negatives at keep-rate w<1w < 1w<1, map served score psp_sps​ to the true-rate probability (ML System Design Prep):

ptrue=psps+(1−ps)/wp_{\mathrm{true}} = \frac{p_s}{p_s + (1-p_s)/w}ptrue​=ps​+(1−ps​)/wps​​

Equivalent to adding ln⁡w\ln wlnw to the logit. Since w<1w<1w<1 that shift is negative: downsampling negatives made positives look more common, so the sampled model overestimates ppp and has to be pulled back down.

Example: w=0.1w=0.1w=0.1, ps=0.5p_s=0.5ps​=0.5 → ptrue≈0.091p_{\mathrm{true}} \approx 0.091ptrue​≈0.091.

Common follow-ups / traps

  • "SMOTE on the full data before CV?" → Leakage — resample inside each training fold only.
  • "99% accuracy on 1% positives" → Likely predicting all-negative; check PR-AUC and recall at your threshold.

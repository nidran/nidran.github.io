Decision Trees, Random Forests & Gradient Boosting

Tree models and their ensembles are the default answer for structured tabular data — if you can explain splits, bagging variance math, and boosting as gradient descent, you own the most-tested classical ML arc.

A single decision tree is an axis-aligned partition of the feature space: a sequence of if/else questions that route each point to a leaf labeled by majority class or mean target. Alone it's interpretable but unstable; random forests and gradient boosting turn that instability into state-of-the-art tabular performance. This chapter goes past the survey in Classification Methods into split criteria with numbers, pruning, ensemble variance, functional gradient boosting, library-specific tricks, feature-importance traps, and when trees still beat deep nets.

What you'll be able to say after this chapter
  • Compute Gini / information gain (or variance reduction) for a candidate split and argue which feature wins.
  • Explain cost-complexity pruning and why an unpruned tree is high-variance.
  • Derive the random forest variance intuition ρσ2+(1−ρ)σ2B\rho\sigma^2 + \frac{(1-\rho)\sigma^2}{B}ρσ2+B(1−ρ)σ2​ and what OOB error estimates.
  • Describe gradient boosting as gradient descent in function space (pseudo-residuals, shrinkage, subsampling).
  • State the XGBoost split gain with λ\lambdaλ, γ\gammaγ, and histogram splits; contrast LightGBM and CatBoost headlines.
  • Compare impurity vs permutation vs SHAP importance and name a sensible hyperparameter tuning order.
  • Argue when GBDT beats neural nets on tabular data (and when it doesn't).

#How a Tree Chooses a Split

At each internal node the algorithm considers every feature and every allowable threshold, scores each candidate split, and keeps the best. "Best" means largest impurity reduction (classification) or largest variance reduction (regression).

#Classification: Gini and entropy

For node ttt with class proportions pkp_kpk​, Gini impurity is

G(t)=1−∑kpk2G(t) = 1 - \sum_k p_k^2G(t)=1−k∑​pk2​

Entropy is H(t)=−∑kpklog⁡2pkH(t) = -\sum_k p_k \log_2 p_kH(t)=−∑k​pk​log2​pk​. A split into left (LLL) and right (RRR) children with weights wL=nL/nw_L = n_L/nwL​=nL​/n, wR=nR/nw_R = n_R/nwR​=nR​/n yields information gain

ΔI=I(t)−wL I(L)−wR I(R)\Delta I = I(t) - w_L\, I(L) - w_R\, I(R)ΔI=I(t)−wL​I(L)−wR​I(R)

where III is Gini or entropy. Splits maximize ΔI\Delta IΔI (equivalently minimize weighted child impurity). Gini and entropy usually agree; Gini skips logs and is the default in sklearn/CART.

For multiclass, the same formulas use all KKK classes; some libraries also support binary-only impurity (faster on many-class problems).

#Regression: variance reduction

For targets yiy_iyi​ in a node with mean yˉ\bar{y}yˉ​, node variance is 1n∑(yi−yˉ)2\dfrac{1}{n}\sum (y_i - \bar{y})^2n1​∑(yi​−yˉ​)2. A split is scored by how much weighted child variance drops — exactly the MSE improvement you'd get by assigning each point to the child whose mean is closer.

Memory hook

Gini = "how often would a random label in this node be wrong if you guessed by the local class frequencies?" High Gini = mixed labels = worth splitting.

Interview angle

Weak: "we use Gini." Strong: we minimize impurity / maximize information gain; for regression that's within-node MSE. Splits are axis-aligned and greedy — no global optimum guarantee.

Rapid fire — Splits
  • Classification: minimize weighted Gini or maximize information gain from entropy.
  • Regression: maximize variance / MSE reduction.
  • Splits are axis-aligned, greedy, local optima.
  • Gini ≈ entropy in practice; Gini is cheaper.
  • Multiclass uses the same formulas over all classes.

#Stopping, Pruning, and Why Trees Are High-Variance

#Growing and stopping criteria

Trees grow until stopped by:

Criterion Effect
Max depth Hard cap on interactions
Min samples per leaf Stops splitting tiny, pure-by-chance regions
Min impurity decrease Ignores splits that barely help
Max leaf nodes Budget on complexity

Defaults that allow full growth (min samples = 1, no depth cap) memorize training noise — classic overfitting.

#Cost-complexity pruning (CART)

Post-pruning starts from a large tree T0T_0T0​ and trades fit against size. Define cost-complexity

Rα(T)=R(T)+α∣T∣R_\alpha(T) = R(T) + \alpha \vert T \vertRα​(T)=R(T)+α∣T∣

where R(T)R(T)R(T) is misclassification rate (or node MSE), ∣T∣\vert T \vert∣T∣ is leaf count, and α≥0\alpha \geq 0α≥0 penalizes size. As α\alphaα increases, subtrees with small impurity gains get pruned first. Cross-validation on a grid of α\alphaα picks the subtree that generalizes best — the honest alternative to hand-tuning max depth.

Memory hook

Pruning = pay a tax α\alphaα per leaf so the tree can't buy tiny purity wins that don't survive validation.

#High variance without ensembles

Property Consequence
Low bias (deep trees) Can fit complex interactions
High variance Small label noise / subsample changes flip early splits → a completely different tree
Discontinuous boundary Step functions; no smooth extrapolation
Greedy splits Early mistakes propagate

This is exactly why bias-variance interviews pair "deep tree" with variance, and why bagging targets variance while boosting targets bias. See Decision Trees for the card-level summary.

Interview angle

"Why not one deep tree?" → near-zero training error but unstable test performance; averaging or sequential correction fixes the pathology the inductive bias creates.

Rapid fire — Pruning & variance
  • Stop with depth, min samples, min gain, or leaf budget.
  • Cost-complexity Rα=R+α∣T∣R_\alpha = R + \alpha \vert T \vertRα​=R+α∣T∣; CV on α\alphaα selects subtree.
  • Single deep trees: low bias, high variance, unstable.
  • Regression leaves predict constants — no extrapolation.

#Random Forests: Bootstrap, Feature Bagging, OOB

Random forests are bagging over deep CART trees with an extra randomization: at each split, consider only a random subset of mmm features (often m≈dm \approx \sqrt{d}m≈d​ for classification, d/3d/3d/3 for regression).

#The two sources of randomness

  1. Bootstrap samples: each tree trains on nnn points drawn with replacement (~63% unique rows per tree).
  2. Feature subsampling at splits: decorrelates trees that would otherwise all chase the same dominant feature.

Goal: keep individual trees low-bias (deep) but make them diverse so averaging reduces variance.

#OOB error

Each point is left out of roughly 1/3 of trees (not in their bootstrap bag). Out-of-bag (OOB) predictions aggregate only those trees and give a free validation estimate without a holdout set — useful for monitoring, though you still want a proper cross-validation split for model selection.

#Variance of the ensemble average

Let BBB trees each predict Tb(x)T_b(x)Tb​(x) with variance σ2\sigma^2σ2 and pairwise correlation ρ\rhoρ between tree predictions. The forest prediction is Tˉ(x)=1B∑bTb(x)\bar{T}(x) = \frac{1}{B}\sum_b T_b(x)Tˉ(x)=B1​∑b​Tb​(x). Then

Var(Tˉ)=ρ σ2+1−ρB σ2\mathrm{Var}(\bar{T}) = \rho\,\sigma^2 + \frac{1 - \rho}{B}\,\sigma^2Var(Tˉ)=ρσ2+B1−ρ​σ2

Intuition: correlated trees contribute ρσ2\rho\sigma^2ρσ2 that doesn't shrink with BBB; only the uncorrelated fraction (1−ρ)σ2(1-\rho)\sigma^2(1−ρ)σ2 dies as 1/B1/B1/B. Feature subsampling exists to lower ρ\rhoρ. Adding more trees can't fix fully correlated errors — diversity is the lever.

Memory hook

Forest variance = correlation floor ρσ2\rho\sigma^2ρσ2 plus a diversity bonus that vanishes as 1/B1/B1/B.

Interview angle

Trap: "forests can't overfit if you add trees." Partially true for training loss, but test error plateaus — ρσ2\rho\sigma^2ρσ2 remains. Overfitting still happens via depth, leaf size, and overfitting to a fixed feature set.

Rapid fire — Random forests
  • Bootstrap rows + random features per split.
  • OOB ≈ built-in validation; still use proper CV for selection.
  • Var(Tˉ)=ρσ2+(1−ρ)σ2/B\mathrm{Var}(\bar{T}) = \rho\sigma^2 + (1-\rho)\sigma^2/BVar(Tˉ)=ρσ2+(1−ρ)σ2/B — correlation limits gains.
  • Deep trees, low tuning, strong tabular default — see Bagging vs Boosting.

#Gradient Boosting as Functional Gradient Descent

Boosting builds an additive model FM(x)=∑m=1Mη hm(x)F_M(x) = \sum_{m=1}^{M} \eta\, h_m(x)FM​(x)=∑m=1M​ηhm​(x) where each hmh_mhm​ is a weak learner (typically a shallow tree).

#Pseudo-residuals

Given loss ℓ(y,F(x))\ell(y, F(x))ℓ(y,F(x)), gradient boosting (Friedman) sets

Fm(x)=Fm−1(x)+η hm(x)F_m(x) = F_{m-1}(x) + \eta\, h_m(x)Fm​(x)=Fm−1​(x)+ηhm​(x)

and fits hmh_mhm​ to the negative gradient of the loss w.r.t. Fm−1F_{m-1}Fm−1​:

rim=−∂ℓ(yi,F(xi))∂F∣F=Fm−1r_{im} = -\left.\frac{\partial \ell(y_i, F(x_i))}{\partial F}\right|_{F = F_{m-1}}rim​=−∂F∂ℓ(yi​,F(xi​))​​F=Fm−1​​

For squared loss, rim=yi−Fm−1(xi)r_{im} = y_i - F_{m-1}(x_i)rim​=yi​−Fm−1​(xi​) — ordinary residuals. For log-loss, residuals look like y−py - py−p (classification pseudo-responses). This is gradient descent in function space, not weight space — see Gradient Descent.

#Shrinkage and subsampling

  • Learning rate η\etaη (shrinkage): smaller steps need more trees but usually generalize better — tune η\etaη and MMM together (low η\etaη, more estimators).
  • Subsampling (stochastic boosting): each round fits on a random fraction of rows (and sometimes columns), injecting noise like bagging and reducing overfitting.

Shallow trees (depth 3–8) keep each hmh_mhm​ a weak learner; depth sets max interaction order (2d2^d2d leaves).

Memory hook

Boosting = steepest descent where each step is a small tree fit to the loss gradient — not relabeling mistakes only (that's AdaBoost's story), but the same "fix what's wrong" spirit.

Rapid fire — Gradient boosting core
  • Additive model; each tree fits negative loss gradient (pseudo-residuals).
  • Squared loss → residual targets; log-loss → y−py - py−p-style targets.
  • η\etaη shrinks steps; row subsampling regularizes.
  • Shallow trees, many rounds — bias↓, watch overfitting.

#XGBoost, LightGBM, and CatBoost

Libraries differ in how they find splits, grow trees, and handle categoricals — the gain formula and growth strategy are fair game in senior interviews.

#XGBoost: second-order Taylor + regularized splits

XGBoost approximates the loss with a second-order Taylor expansion at current predictions Fm−1F_{m-1}Fm−1​:

ℓ(y,Fm−1+f)≈ℓ(y,Fm−1)+g f+12h f2\ell(y, F_{m-1} + f) \approx \ell(y, F_{m-1}) + g\, f + \frac{1}{2} h\, f^2ℓ(y,Fm−1​+f)≈ℓ(y,Fm−1​)+gf+21​hf2

with g=∂Fℓg = \partial_F \ellg=∂F​ℓ and h=∂F2ℓh = \partial_F^2 \ellh=∂F2​ℓ (gradient and Hessian). For squared loss, h=1h = 1h=1; for log-loss, h=p(1−p)h = p(1-p)h=p(1−p).

Summing over instances in a leaf with score www, the optimal leaf weight solves

w∗=−GH+λw^* = -\frac{G}{H + \lambda}w∗=−H+λG​

where G=∑giG = \sum g_iG=∑gi​, H=∑hiH = \sum h_iH=∑hi​, and λ\lambdaλ is L2 on leaf weights. The split gain for a partition into LLL and RRR is

Gain=12[GL2HL+λ+GR2HR+λ−(GL+GR)2HL+HR+λ]−γ\mathrm{Gain} = \frac{1}{2}\left[\frac{G_L^2}{H_L + \lambda} + \frac{G_R^2}{H_R + \lambda} - \frac{(G_L + G_R)^2}{H_L + H_R + \lambda}\right] - \gammaGain=21​[HL​+λGL2​​+HR​+λGR2​​−HL​+HR​+λ(GL​+GR​)2​]−γ

γ\gammaγ is a minimum gain threshold (complexity penalty per split); λ\lambdaλ shrinks leaf scores. Splits with negative gain are pruned.

Histogram splits: bin continuous features once, then search split candidates on bin boundaries — O(#bins⋅d)O(\#\mathrm{bins} \cdot d)O(#bins⋅d) per node instead of sorting all nnn. Column blocks and cache-aware design explain much of its speed.

Interview angle

Write the gain without forgetting −γ- \gamma−γ and the λ\lambdaλ in every denominator. Weak: "XGBoost is fast." Strong: second-order approximation, regularized leaf weights, histogram-based candidate splits.

#LightGBM: leaf-wise growth, GOSS, EFB

  • Leaf-wise (best-first) growth: split the leaf with largest loss reduction — deeper asymmetric trees for fixed leaf budget vs level-wise sklearn GBM. Risk: overfits if num_leaves is too large without min_data_in_leaf.
  • GOSS (Gradient-based One-Side Sampling): keep large-gradient instances, random sample small-gradient ones — speeds training with minimal accuracy loss when gradients carry the signal.
  • EFB (Exclusive Feature Bundling): merges sparse mutually exclusive one-hot columns to reduce dimensionality.

#CatBoost: ordered boosting and categoricals

  • Ordered boosting: computes gradients with permutation-based statistics so target leakage across boosting iterations is reduced (important when residuals reuse labels).
  • Target statistics for categoricals: smooth counts like nk+α pn+α\dfrac{n_k + \alpha\, p}{n + \alpha}n+αnk​+αp​ with priors instead of naive one-hot explosion — strong on high-cardinality categoricals without manual encoding.
Library Signature trick Watch
XGBoost 2nd-order gain + λ\lambdaλ, γ\gammaγ; histogram More knobs; level-wise default in some APIs
LightGBM Leaf-wise, GOSS, EFB num_leaves can overfit
CatBoost Ordered boosting + native categoricals Slower on tiny data; GPU helps
Rapid fire — GBDT libraries
  • XGBoost gain uses GGG, HHH, λ\lambdaλ, subtract γ\gammaγ per split.
  • Histogram binning for speed at scale.
  • LightGBM: leaf-wise, GOSS, EFB.
  • CatBoost: ordered stats, ordered boosting for categoricals.

#Feature Importance: Impurity, Permutation, SHAP

Method What it measures Pitfall
Impurity decrease (MDI) How much a feature reduced Gini/MSE in the forest Biased toward high-cardinality / continuous features with many split points
Permutation importance Drop in validation metric when feature values are shuffled Needs held-out data; correlated features share importance
SHAP (tree explainer) Consistent additive attributions from cooperative game theory Costly; still reflects training distribution

Senior habit: use impurity for rough screening, permutation on a validation set for honest global ranking, SHAP for local explanations and debugging individual predictions — tie back to Model Evaluation & Validation and Data Leakage (importance on leaky features lies).

Importance ≠ causality. A feature can rank high because it's a proxy for the label or because of leakage, not because intervening on it would change outcomes.

#Hyperparameter Tuning Order

A practical sequence for GBDT (adapt for forests by dropping η\etaη/MMM tradeoffs):

  1. learning_rate η\etaη + n_estimators — fix a modest η\etaη (0.03–0.1), use early stopping on validation to set rounds.
  2. max_depth / num_leaves — interaction capacity; shallow first, then increase if underfitting.
  3. min_child_weight / min_data_in_leaf — smooth leaves, reduce noise fits.
  4. subsample + colsample_bytree — regularization once structure is right.
  5. reg_lambda, reg_alpha, gamma — fine-grain split/leaf penalties.
  6. Class weights or scale_pos_weight for class imbalance before chasing exotic losses.

Random forests: tune max_depth, min_samples_leaf, max_features, then n_estimators until OOB/validation plateaus.

Use Cross-Validation on the same preprocessing you'd ship — see Data Preparation & Feature Engineering.

Interview angle

"How do you tune XGBoost?" → early stopping on learning rate and rounds first, then tree complexity, then stochastic fractions, then regularization — never tune 15 knobs randomly.

#When Trees Beat Neural Nets on Tabular Data

Gradient-boosted trees often win when:

  • Moderate nnn (thousands to millions), heterogeneous column types (numeric + categorical + missing).
  • Low signal-to-noise where inductive bias toward axis-aligned splits helps.
  • Need fast CPU training, interpretable partial dependence, little GPU ops burden.
  • Irregular interactions without spatial structure (unlike images/text).

Neural nets tend to win when:

  • Massive data, rich perception (vision, audio, language) or sequences.
  • End-to-end representation learning beats hand features.
  • Homogeneous tensor data with translation/equivariance structure (CNNs).

Recent benchmarks (e.g. TabTransformer-era studies) still show strong GBDT on many business tabular sets unless you invest heavily in embeddings and regularized deep architectures — see Training Neural Networks for the flip side.

Rapid fire — Trees vs nets
  • Tabular heterogeneous data → GBDT default; NN needs careful embeddings/regularization.
  • Trees handle missing indicators natively in many libs; NNs need explicit handling.
  • Trees: fast on CPU, partial dependence; NNs: scale on GPU for perceptual/modal data.
  • Always benchmark — No Free Lunch.

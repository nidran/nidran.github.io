Data Preparation & Feature Engineering

Models learn from what you feed them — garbage features beat clever algorithms every time.

Feature work is where many interviews go deep: not because formulas are hard, but because judgment is — knowing when a transform helps, when it leaks, and when imbalance demands a different loss and metric. The best candidates narrate a pipeline end to end: audit the table, define the label at the right time, split without cheating, encode for the model family, and pick metrics that match the business asymmetry — then show the sklearn Pipeline that enforces it. This chapter walks data quality through encoding, transforms, selection, leakage (Data Leakage), class imbalance (Class Imbalance), and honest train/validation/test splits aligned with cross-validation and evaluation practice.

What you'll be able to say after this chapter
  • Run a data quality checklist before modeling.
  • Handle missing data (MCAR/MAR/MNAR) and pick imputation vs missing indicators.
  • Scale and encode features for the right model family without leakage.
  • Engineer numeric, text, and datetime signals; select features with filter/wrapper/embedded tools.
  • Classify leakage types with examples and prevent them with pipelines.
  • Address imbalance and split data by groups and time correctly.

#Data quality checks

Before featurizing, interrogate the table:

Check What to look for Why it matters
Schema & types IDs stored as floats, dates as strings Silent coercion bugs in training
Duplicates Exact dupes, same user-timestamp Inflated metrics, wrong splits
Cardinality Constant columns, near-unique junk Zero information or memorization
Outliers & range Negative ages, 10⁹ "seconds" Breaks scaling and linear models
Label sanity Prevalence, temporal gaps Wrong baseline, wrong metric
Join integrity Orphan keys after merges Missing-not-at-random bias

Profile train and (future) production separately — drift in quality often precedes drift in model scores.

Automate checks in a validation gate before each training run: assert label column never null, assert timestamp monotonicity for event streams, and alert when categorical cardinality jumps (new enum values in production). These gates catch silent schema breaks that models cannot learn around.

Interview angle

"Walk me through starting a new tabular problem." Open with data quality and label definition, not "I'll try XGBoost."

#Target definition and label hygiene

Before featurizing, freeze what you predict and when the label is known. Churn at 30 days is not the same problem as churn at 7 days — horizons change prevalence and feature eligibility. Document inclusion rules (active users only, minimum activity) so train and serve use the same population. Wrong labels poison every downstream step; no amount of regularization fixes a label that encodes the wrong business question.

Interview angle

"How do you predict churn?" — answer with label definition and prediction time first, then features. Interviewers listen for eligibility filters and whether features exist at scoring time.

#Missing data

MCAR (missing completely at random): drop or simple impute without much bias. MAR (missing at random): missingness depends on observed columns — model it or impute with care. MNAR (not at random): missingness depends on the hidden value itself — no imputation is unbiased without extra structure (e.g. Tobit, explicit missingness model).

Strategy When Caveat
Listwise delete MCAR, few missing Wastes data if not MCAR
Mean / median impute Quick baseline Shrinks variance; use + missing indicator
Model-based (KNN, MICE) MAR, structured Fit inside CV folds only
Learned "missing" token Trees, deep nets Let splits handle absent values
Separate category Unknown Categoricals Don't confuse with a real level

A missing-indicator feature (1 if imputed) lets linear models recover different slopes for imputed rows.

Decision rule of thumb: if <5%<5\%<5% missing and MCAR plausible, median impute + indicator is fine for tree/linear baselines. If missingness correlates with the label (MNAR suspicion), model whether missingness is informative — or drop features you cannot defend at inference time.

Memory hook

MCAR = dropped coins; MAR = missingness you can explain from other columns; MNAR = the secret itself drives absence.

#Scaling numeric features

Method Formula (per column) Robust to outliers?
Standardization (x−μ)/σ(x - \mu) / \sigma(x−μ)/σ No
Min–max (x−min⁡)/(max⁡−min⁡)(x - \min) / (\max - \min)(x−min)/(max−min) No — dominated by extremes
Robust (x−median)/IQR(x - \mathrm{median}) / \mathrm{IQR}(x−median)/IQR Better for heavy tails

Needs scaling: distance models (k-NN, SVM RBF), neural nets, linear/logistic with gradient descent, k-means. Often indifferent: tree ensembles (splits are rank-invariant). Rule: if the algorithm cares about magnitude or dot products, scale; fit scaler on training only.

Rapid fire — Missing & scale

Name MCAR/MAR/MNAR before imputing. Indicators + imputation for MAR tabular. Robust scaling when outliers matter. Trees don't need scale; linear and NN do. Fit transforms on train.

#Encoding categoricals

Encoding High-cardinality? Leakage risk
One-hot Poor if thousands of levels Low if fit on train categories only
Ordinal When order is real Wrong order hurts linear models
Target / mean encoding Strong for high card High — needs out-of-fold stats
Hashing Very high card, streaming Collisions trade bias for memory
Embeddings Very high card, deep nets Learned; watch rare levels

Target encoding replaces category ccc with smoothed mean label μ~c\tilde\mu_cμ~​c​ estimated on training rows with label ccc only — compute per fold on the other folds' training portion (K-fold target encoding) to avoid label leakage into validation. Add smoothing toward global mean for rare categories.

For high cardinality (user ids, zip codes): hash, frequency encoding, bucket rare levels to Other, or embeddings in tree/NN hybrids.

Frequency encoding maps a level to its training count or log-count — smooth for trees, leaky if computed on train+val together. Embedding layers learn dense vectors for sparse IDs in neural nets; rare levels need min-frequency cutoffs or a shared UNK bucket. In interviews, tie encoding choice to data volume and model family: one-hot blows up sparse linear models; target encoding helps GBDT on categoricals when done out-of-fold.

Target encoding on full train before CV

The validation fold sees its own labels in the encoding — classic leakage. Always out-of-fold.

#Numeric transforms, interactions, and binning

  • Log / Box–Cox: right-skewed counts, multiplicative effects → approximate normality for linear models.
  • Binning: capture nonlinearities for linear models; trees do this implicitly.
  • Interactions: x1×x2x_1 \times x_2x1​×x2​ when domain says joint effect (price × discount); explosive dimension — prefer models that learn interactions (GBDT, NNs) when data is ample.

Pair transforms with interpretability needs: stakeholders may want monotonic bins; NNs may want raw + embeddings.

#Text and datetime features

Text: tokenization, n-grams, TF–IDF for classical baselines; pretrained embeddings or fine-tuned encoders for depth (classification pipelines). Normalize case and unicode consistently with production.

Datetime: decompose into hour, day-of-week, month, holidays, time-since-event; for series, lags and rolling stats with strict causal windows (only past data). See time series splitting below.

Cyclic encoding helps linear models respect wrap-around: sin⁡(2πh/24),cos⁡(2πh/24)\sin(2\pi h/24), \cos(2\pi h/24)sin(2πh/24),cos(2πh/24) for hour, same for day-of-week. Raw integers imply hour 23 is far from hour 0. For recency features, compute Δt=tnow−tlast event\Delta t = t_{\text{now}} - t_{\text{last event}}Δt=tnow​−tlast event​ using the same clock as serving — training backfills with warehouse as_of timestamps prevent subtle future peeking.

#Text feature ladder

Stage Representation When
Bag-of-words / TF–IDF Sparse n-grams Strong baseline, interpretable
Char n-grams Subword robustness Typos, morphology
Pretrained embeddings Average or pool token vectors Medium data, transfer
Fine-tuned encoder End-to-end task loss Enough labels, compute budget

Start simple: TF–IDF + logistic regression often beats an under-trained BERT in interviews because it's fast, debuggable, and pairs with logistic regression intuition. Move up the ladder when offline metrics plateau and latency budget allows.

Interview angle

"Features for fraud?" Mix velocity (counts in 1h), device graph signals, and time since last event — always ask what's known at decision time (leakage).

#Feature selection

Family Idea Cost
Filter Correlation, mutual information, chi-square Cheap; ignores model
Wrapper Forward/backward stepwise on validation score Expensive; overfits small nnn
Embedded L1 (lasso paths), tree importance Built into training
Permutation importance Shuffle one column, measure metric drop Model-aware; compute on validation

Drop collinear features for linear models; trees tolerate redundancy but importance gets muddy. Permutation on test once at the end; tune selection on validation inside CV.

Wrapper vs embedded trade-off: stepwise selection with logistic regression can overfit when nnn is small — each added feature is tuned on the same validation slice. L1 (lasso) path gives a sparse model in one shot; gradient boosting importance is fast but favors high-cardinality columns — use permutation importance to sanity-check. For interviews, name one filter method (mutual information), one embedded (L1), and permutation as the honest check.

#Data leakage

Full taxonomy — see Data Leakage card:

Type Example Fix
Target leakage "Refund issued" predicting purchase Drop post-outcome fields
Train–test contamination Same user in train and test Group split
Temporal leakage Random shuffle on time series Time-based split
Preprocessing leakage StandardScaler on all data before split Pipeline fit on train only

Aggregate leakage: target encoding or global counts computed including test users — fix with per-fold or streaming estimators.

Walk the same checklist when tuning hyperparameters: if each trial refits encoders on train+validation labels, you leak selection signal. Nested cross-validation separates outer honest estimation from inner tuning — expensive but correct when stakes are high (Cross-Validation, overfitting).

Rapid fire — Leakage

Features must exist at prediction time. Split before fit. Groups and time are not optional. Target encoding = out-of-fold only. Suspicious offline AUC → audit joins first.

#Class imbalance

Rare positives break accuracy and default thresholds (Precision & Recall, PR-AUC):

Technique Role
Class weights Reweight loss — cheap, no duplicate rows
Undersample majority Faster training; loses data
Oversample / SMOTE Synthetic minority points along borders — overuse blurs boundaries; only inside train folds
Threshold move Tune on PR curve on validation
Focal loss Down-weight easy negatives in deep nets ([[loss-functions

Pick metrics that reflect the business: PR-AUC, recall at fixed precision, cost-sensitive utility. After resampling, recalibrate if probabilities matter (Calibration).

#SMOTE caveats (expanded)

SMOTE interpolates between a minority point and its k nearest minority neighbors — synthetic points lie on chords in feature space. It helps when the minority class is tiny and the boundary is smooth; it hurts when features are mostly categorical or when noise dimensions dominate (synthetic points land in nonsense regions). Never apply SMOTE before splitting — duplicates the minority into validation. Prefer class weights first on large data; SMOTE is a scalpel for small tabular sets with continuous features.

Cost-sensitive learning bakes business asymmetry into the loss: false negative cost 100× false positive → weight positives 100× or optimize a custom utility at a chosen threshold. This is cleaner than resampling when costs are asymmetric but known (Loss Functions).

Problem type Split strategy
i.i.d. tabular Random 60/20/20 or nested CV ([[cross-validation
Grouped (user, patient) GroupKFold — all rows of a group in one fold
Temporal Train on past, validate on future; expanding window
Spatial / market Hold out geos for true generalization

Fundamentals golden rule: touch test once. Hyperparameters and thresholds consume validation only.

#Leakage-safe sklearn pipeline

Fit preprocessors on training data only; chain with the estimator:

from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.impute import SimpleImputer
from sklearn.linear_model import LogisticRegression

num_cols = ["age", "income"]
cat_cols = ["country"]

preprocess = ColumnTransformer(
    transformers=[
        (
            "num",
            Pipeline([
                ("imputer", SimpleImputer(strategy="median")),
                ("scaler", StandardScaler()),
            ]),
            num_cols,
        ),
        (
            "cat",
            Pipeline([
                ("imputer", SimpleImputer(strategy="constant", fill_value="Unknown")),
                ("onehot", OneHotEncoder(handle_unknown="ignore")),
            ]),
            cat_cols,
        ),
    ]
)

model = Pipeline(steps=[
    ("preprocess", preprocess),
    ("clf", LogisticRegression(max_iter=1000)),
])

# X_train, y_train only — never fit on validation or test
model.fit(X_train, y_train)
y_val = model.predict(X_val)

In cross-validation, wrap the entire pipeline in cross_val_score so each fold refits imputer and scaler on that fold's train slice only.

#Feature engineering vs feature stores

In production (ML system design), point-in-time correct features come from a feature store: every training row joins attributes as they were known at that timestamp, not today's snapshot of the user. Training on current aggregates (total lifetime spend) to predict past events is subtle temporal leakage — offline AUC soars, live model flatlines.

Go deeper (optional)

Polynomial features explode dimension on wide tables; use only with strong regularization or low-dimensional domain picks. Entity embeddings pre-trained on co-occurrence can transfer cold-start signal for recommender-style problems (Recommender Systems).

Memory hook

Pipeline = "every transform is part of the model, trained where the model is trained."

Interview angle

"How do you prevent leakage in sklearn?" — ColumnTransformer + Pipeline, fit on train or inside CV; never fit on concatenated train+val.

Rapid fire — Splits & imbalance

Group split for repeated entities. Time split for series. SMOTE only in train folds. Class weights often enough. Threshold ≠ 0.5. Pipeline fit on train.

#Model-aware feature choices

Different learners expose different failure modes — feature prep should match.

Model family Encoding / scaling notes
Linear / logistic Scale continuous; one-hot or OOF target encode; watch multicollinearity
k-NN, SVM (RBF) Scale mandatory; distance metrics suffer from mixed units
Tree / GBDT Unscaled OK; target encoding helps high-cardinality categoricals
Neural nets Standardize inputs; embeddings for sparse IDs; watch embedding dimension vs data
Naive Bayes Discretize heavy tails; independence assumption hates redundant copies

Classification and regression chapters assume these prep choices; mismatches (linear on unscaled dollar amounts) show up as "the model didn't learn" when the pipeline was wrong.

#Worked split example (groups + time)

E-commerce click prediction: rows are impression-level, but users repeat. Wrong: random 80/20 row split — same shopper in train and test. Right: GroupKFold by user_id for validation; hold out the last 7 days globally for test so features use only past behavior. Imputation and scaling live in the pipeline fitted on train users only; future users with unseen countries hit handle_unknown='ignore' on the one-hot encoder.

Validation optimism on grouped data

If groups are huge (enterprise accounts), a single fold may contain entire whales — report variance across folds, not one lucky split.

Rapid fire — Model-aware prep

Linear needs scale + careful categoricals. Trees eat raw-ish tables with good encodings. NNs need normalized inputs + embeddings. Match prep to the inductive bias. Group+time splits for behavioral data.

Data quality Profile types, dupes, label prevalence before modeling.
Missingness MCAR/MAR/MNAR drives strategy; add missing indicators.
Scaling For distance/linear/NN; fit on train; robust if heavy tails.
Encoding One-hot for low card; hashed/target/emb for high card — OOF for target.
Transforms Log/Box–Cox for skew; interactions when domain demands.

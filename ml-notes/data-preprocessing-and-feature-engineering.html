Data Preprocessing & Feature Engineering

Data & Features: what happens to the data before the model sees it, and why most "surprisingly good" offline results trace back to this stage.

In most applied settings the model family matters less than the data handling around it. A gradient-boosted tree trained on leaky features will beat a carefully tuned model trained on clean ones, and then fail in deployment. This chapter covers the pipeline in the order it should be built: split first, then clean, encode, transform, balance, and select, with every fitted step living inside the training fold. The recurring theme is a single rule: anything learned from data must be learned from training data only.

What you'll be able to say after this chapter
  • Describe a leakage-safe pipeline and name the four leakage families with a detection tip for each.
  • Distinguish MCAR, MAR, and MNAR, and pick an imputation strategy with a missing-indicator when missingness is informative.
  • State which model families need feature scaling and why trees do not.
  • Implement target encoding with out-of-fold statistics and smoothing.
  • Explain how resampling and class weights shift predicted probabilities, and how to correct for it.
  • Compare filter, wrapper, and embedded feature selection, and say where each can leak.

#Split Hygiene: Train, Validation, Test

Each split has a single job, and mixing jobs is the root of most optimistic estimates.

Split Job Touched how often
Train Fit parameters (weights, tree splits) and every preprocessing statistic (means, vocabularies, encodings) Constantly
Validation Choose hyperparameters, features, thresholds, model family Many times (this is what makes it optimistic over time)
Test One unbiased estimate of final performance Once, after all decisions are frozen

With cross-validation, the validation role rotates across folds and a separate test set is still kept aside when the number of model-selection decisions is large. See Cross-Validation for nested CV, which separates selection from estimation when data is scarce.

Practical rules:

  • Split before any fitting. Even "harmless" steps such as computing a column mean or fitting a vocabulary belong after the split.
  • Match the split to deployment. If the model will score future rows, split by time. If it will score new users, entities, or sites, split by group. A random split is only appropriate when the deployment distribution of new rows is exchangeable with the training rows.
  • Stratify when classes are rare, so that every fold contains enough positives to estimate metrics (stratification stabilizes estimates; it does not fix leakage).
  • Deduplicate first. Exact and near-duplicate rows (repeated scrapes, augmentations, re-submitted records) that straddle the split inflate scores.
  • Freeze the test set. Each look at test performance that informs a decision converts it into a second validation set.
Interview angle

"How would you split the data?" is rarely about percentages. The strong answer starts from the unit of generalization: what will be new at prediction time (a later date, a new customer, a new device)? Then the split mirrors that, and the preprocessing is fit inside the training portion only.

#Data Leakage

Leakage is any pathway by which information unavailable at prediction time influences training or evaluation. The symptom is an offline score that is too good and a production score that is not. Four families cover most cases.

Family Mechanism Typical example Detection tips
Target leakage A feature encodes the label or is produced after the outcome "Number of collections calls" as a feature for loan default; a discharge code predicting a diagnosis Single feature with implausibly high importance or single-feature AUC near 1; ask of each feature "when is this value written, relative to the prediction time?"
Train-test contamination Information from held-out rows enters fitting Scaling or imputing on the full dataset; selecting features on all data; target encoding without cross-fitting; duplicates across splits Compare a pipeline fit on train only against one fit on all data; check duplicate and near-duplicate overlap between splits
Temporal leakage Future information is used to predict the past Random split on time-ordered data; rolling features computed with the current or future rows; labels that mature after the cutoff Re-run with a forward-chaining split and see whether the score drops; verify that every feature has an event timestamp not later than the prediction timestamp
Group leakage Correlated rows from the same entity are on both sides Multiple images per patient, many sessions per user, several rows per household Evaluate with grouped splits; a large gap between random-CV and group-CV scores indicates entity memorization

Further patterns worth knowing:

  • Label-derived features. Aggregates (such as per-user conversion rate) that include the current row's label.
  • Selection and survivorship bias in the label. Labels that exist only for rows that passed an earlier filter (for example, loan outcomes exist only for approved applicants). This is a bias in the training distribution rather than leakage in the strict sense, but it produces the same offline-online gap.
  • Preprocessing order. Resampling or augmenting before splitting places near-copies of a row in both train and validation.
  • Identifier leakage. Row IDs, file names, or timestamps that correlate with the label because of how the data was collected.
A useful smell test

If one feature dominates importance, or a quick model reaches near-perfect accuracy on a problem that is known to be hard, the likely explanation is a leak rather than a modelling success. Inspect that feature's definition and timestamp before celebrating.

Go deeper (optional)

Leakage can also be introduced by the evaluation loop. Repeatedly choosing among many candidate models on the same validation set overfits to it, and the winner's score is an optimistically biased estimate. The cure is a fresh holdout or nested CV, as covered in Model Evaluation & Validation.

#Missing Data

Before choosing a fix, ask why values are missing. Rubin's taxonomy describes the dependence between the missingness indicator MMM and the data, split into observed values XobsX_{obs}Xobs​ and missing values XmisX_{mis}Xmis​.

Mechanism Definition Example Consequence
MCAR (completely at random) P(M∣X)=P(M)P(M \mid X) = P(M)P(M∣X)=P(M) Sensor packet loss unrelated to anything Dropping rows is unbiased (but loses power); most imputers behave acceptably
MAR (at random) P(M∣X)=P(M∣Xobs)P(M \mid X) = P(M \mid X_{obs})P(M∣X)=P(M∣Xobs​) Income missing more often for younger respondents, and age is recorded Model-based imputation conditional on observed variables can be unbiased; complete-case analysis generally is biased
MNAR (not at random) P(M∣X)P(M \mid X)P(M∣X) depends on XmisX_{mis}Xmis​ itself High earners decline to report income No purely data-driven fix is guaranteed; need domain assumptions, sensitivity analysis, or a missing-indicator that captures the pattern

MAR versus MNAR cannot be established from the observed data alone, since the difference lies in the unobserved values. The choice is a modelling assumption supported by domain knowledge.

#Options

Approach How Strengths Limits
Drop rows / columns Complete-case analysis Simple Biased unless MCAR; can discard most of the data if many columns are partly missing
Constant / mean / median Fill with a training-set statistic Fast, keeps all rows Shrinks variance and attenuates correlations; median is more robust to skew
Group-wise statistics Fill with the mean within a segment Uses structure Segment sizes must be adequate; the group means come from training data
kNN / iterative (chained equations) Predict each feature from the others Captures relationships (supports MAR) Costly; must be fit inside folds; a single imputation understates uncertainty
Multiple imputation Draw several completed datasets, pool results Propagates imputation uncertainty Mostly used for inference; heavier for prediction pipelines
Native handling Gradient-boosted trees learn a default direction for missing values at each split No imputation step, can exploit informative missingness Library-dependent; linear and distance-based models still need imputed values
Missing indicator Add a binary column mj=1[xj missing]m_j = \mathbb{1}[x_j \text{ missing}]mj​=1[xj​ missing] alongside imputation Lets the model use missingness as signal (relevant under MNAR or MAR-with-signal) Doubles columns for each affected feature; can add noise if missingness is uninformative
Interview angle

A solid default: impute with a training-fold median (numeric) or a dedicated "missing" level (categorical), and add a missing indicator for features where missingness is plausibly informative. Then check, with a model trained on the indicators alone, whether missingness predicts the label. The statement "it depends on the mechanism" is correct but is only the opening line; follow it with what to do in each case.

Pitfalls: imputing before the split leaks statistics; imputing the target is a different problem and is rarely appropriate; and train and serving pipelines must apply the same imputation values (see ML in Production & Monitoring).

#Scaling and Normalization

Two common transformations, both fit on training data and then applied unchanged to validation, test, and serving data:

z=x−μtrainσtrainx′=x−xminxmax−xminz = \frac{x - \mu_{train}}{\sigma_{train}} \qquad\qquad x' = \frac{x - x_{min}}{x_{max} - x_{min}}z=σtrain​x−μtrain​​x′=xmax​−xmin​x−xmin​​

Standardization (left) yields zero mean and unit variance on the training set; min-max (right) maps to [0,1][0,1][0,1] on the training set and can fall outside that range at test time. Robust scaling replaces mean and standard deviation with median and IQR, which reduces sensitivity to outliers.

Model family Is scaling needed? Reason
Decision trees, random forests, gradient-boosted trees Generally no Splits depend only on the ordering of values; monotone transformations leave the tree unchanged
Linear / logistic regression (unregularized, closed-form) Not for fit quality Predictions are invariant to feature scale, but coefficients change units
Regularized linear models (ridge, lasso, elastic net) Yes The penalty acts on coefficient size, so features on larger scales are penalized less; see Regularization
Gradient descent training (linear models, neural networks) Yes, in practice Badly scaled features produce ill-conditioned loss surfaces and slow or unstable optimization
kNN, k-means, RBF-kernel SVM Yes Distances are dominated by the largest-scale feature
PCA Yes (usually standardize) Variance is scale-dependent; otherwise the largest-unit feature dominates the leading components. See Eigenvectors, PCA and SVD
Naive Bayes (Gaussian) Not required Per-feature class-conditional parameters absorb scale
Warning

The statistics must come from the training fold. Fitting a scaler on the entire dataset before splitting leaks the mean and variance of held-out rows. The effect is typically small for large data and larger for small samples or heavy-tailed features, but it is avoidable at no cost.

Batch normalization and layer normalization inside neural networks are a learned, in-model form of the same idea; they do not replace input standardization in every setting but reduce the sensitivity to it.

#Categorical Encoding

Encoding Description Good for Watch out for
One-hot One binary column per level Linear models, neural networks, low-cardinality features Width grows with cardinality; unseen levels at serving time need a rule (all-zero or "other")
Ordinal / integer Map levels to integers Truly ordered categories; tree models in some cases Imposes a spurious order and spacing on nominal variables for linear and distance-based models
Frequency / count Replace level with its training frequency High cardinality, quick baseline Distinct levels with equal counts collide; frequency may drift over time
Target (mean) encoding Replace level with a statistic of the label High-cardinality features with real label signal Leakage if computed with the row's own label; needs smoothing and cross-fitting
Hashing Hash level into kkk buckets Very high or open-ended cardinality, streaming vocabularies Collisions merge unrelated levels; not invertible; signed hashing reduces collision bias
Learned embeddings Dense vector per level, trained with the model Very high cardinality in neural models; levels with shared structure Needs enough examples per level; rare and new levels need fallback buckets

#Target encoding without leakage

The naive version replaces category ccc with the training mean of yyy among rows in ccc. For the row itself, that mean contains its own label, and for rare categories the row's label dominates. The model then learns that the encoding is nearly the label, which fails on new data.

Two corrections, normally applied together:

  1. Smoothing (shrinkage) pulls small categories toward the global mean yˉ\bar yyˉ​:

μ^c=nc yˉc+m yˉnc+m\hat\mu_c = \frac{n_c\,\bar y_c + m\,\bar y}{n_c + m}μ^​c​=nc​+mnc​yˉ​c​+myˉ​​

where ncn_cnc​ is the count in category ccc, yˉc\bar y_cyˉ​c​ its mean label, and mmm a smoothing strength (a hyperparameter tuned on validation). With nc≪mn_c \ll mnc​≪m the encoding is close to the global mean; with nc≫mn_c \gg mnc​≫m it is close to the category mean. This is the posterior mean under a simple Beta-Binomial or Gaussian prior view.

  1. Cross-fitting (out-of-fold encoding). Split the training data into KKK folds. For rows in fold kkk, compute the encoding from the other K−1K-1K−1 folds. At validation, test, and serving time, use the encoding fitted on all of the training data. Leave-one-out variants exist but can leak through the row-removal arithmetic (the encoding of a row shifts deterministically with its own label), so the KKK-fold form is the safer default. For time-ordered data, replace the folds with an expanding window so that each row is encoded using only earlier rows.
Interview angle

Mention both halves: smoothing handles rare levels, cross-fitting handles self-leakage. Also state that nested validation matters: the encoding is part of the model, so it must be refit inside each outer CV fold.

Unseen categories at serving time need an explicit fallback (the global mean for target encoding, an "unknown" bucket for embeddings or one-hot). Rare levels are commonly grouped into an "other" level using a minimum-count threshold set on training data.

#Numeric Transforms

Log and power transforms. For positive, right-skewed variables (income, counts, durations), log⁡(x)\log(x)log(x) or log⁡(1+x)\log(1+x)log(1+x) compresses the tail and turns multiplicative relationships into additive ones. This often helps linear and distance-based models and stabilizes variance; tree models are invariant to monotone transforms of an input, so the transform matters mainly for the target or for combination features. A target log-transform changes what the model optimizes (errors on the log scale), and predictions transformed back via exp⁡(⋅)\exp(\cdot)exp(⋅) estimate the conditional median rather than the mean under symmetric log-scale noise. Box-Cox and Yeo-Johnson are parametric families that fit the exponent from training data.

Binning (discretization). Equal-width or quantile bins turn a number into ordered categories.

Pros Cons
Lets a linear model fit a piecewise-constant nonlinearity Discards within-bin information; creates discontinuities at edges
Reduces the influence of outliers Bin edges are learned from training data and drift over time
Can help interpretability and monotonic constraints Many bins add parameters; trees already choose their own thresholds

For models that can learn nonlinearities natively (trees, neural networks), explicit binning is often unnecessary. For linear models, splines are a smoother alternative.

Other common transforms: clipping to a range, rank or quantile transform (maps to a uniform or normal shape; robust to outliers but loses distances), ratios and differences between features (rate per exposure), and cyclical encoding of periodic features such as hour of day via (sin⁡(2πt/T),cos⁡(2πt/T))(\sin(2\pi t/T), \cos(2\pi t/T))(sin(2πt/T),cos(2πt/T)) so that hour 23 and hour 0 are adjacent.

#Outliers

First separate errors (a negative age, a sensor stuck at its maximum) from rare but valid extremes (a genuinely large purchase). Errors are fixed or removed; valid extremes often carry the signal in fraud and risk problems.

Technique Notes
IQR rule: flag points beyond Q1−1.5 IQRQ_1 - 1.5\,\mathrm{IQR}Q1​−1.5IQR or Q3+1.5 IQRQ_3 + 1.5\,\mathrm{IQR}Q3​+1.5IQR Robust, univariate, a heuristic threshold rather than a law
z-score thresholding Mean and standard deviation are themselves inflated by outliers; the median absolute deviation version is sturdier
Winsorizing / clipping at percentiles Keeps the row, limits leverage; percentiles come from training data
Robust losses (Huber, quantile) Reduce sensitivity without altering the data; see Regression Methods
Isolation forest, local outlier factor Multivariate anomalies, useful for audit rather than automatic deletion

Removing outliers from the evaluation set while keeping them in production flatters the metric. Any cleaning rule is applied to training data; the same transformation (clipping bounds, not deletion) is applied at serving.

#Class Imbalance

When one class is rare (fraud, disease, churn), accuracy is uninformative and training objectives are dominated by the majority. The first move is to choose metrics suited to the problem (PR-AUC, recall at a precision target, cost-weighted loss); see ROC-AUC vs PR-AUC and Precision & Recall. Rebalancing techniques are a second tool and are not required in every case. Strong classifiers trained with a proper scoring rule on imbalanced data often rank well already, and the main issue is choosing a decision threshold.

Lever Mechanism Effect on ranking Effect on probabilities
Class weights Multiply the loss of minority examples by www Can change the fitted model, especially for flexible ones Shifts predicted probabilities upward; they no longer estimate the true event rate
Random undersampling Drop majority rows Faster training; discards information Shifts probabilities upward
Random oversampling Duplicate minority rows Can overfit duplicates (see leakage note below) Shifts probabilities upward
SMOTE and variants Synthesize minority points by interpolating between neighbors Can help weak learners in low dimension Shifts probabilities; see pitfalls
Threshold moving Change the cutoff on the score, leaving training untouched Ranking unchanged Probabilities untouched; the decision changes
Cost-sensitive loss / focal loss Weight by difficulty or by error cost Model-dependent Probabilities generally miscalibrated

#Resampling shifts the prior, and calibration breaks

Suppose the true positive rate is low and negatives are kept with probability β\betaβ (undersampling). Writing ppp for the true posterior and psp_sps​ for the posterior under the resampled distribution, the odds scale by 1/β1/\beta1/β:

ps1−ps=1β⋅p1−p⟹p=β psβ ps−ps+1\frac{p_s}{1-p_s} = \frac{1}{\beta}\cdot\frac{p}{1-p} \quad\Longrightarrow\quad p = \frac{\beta\,p_s}{\beta\,p_s - p_s + 1}1−ps​ps​​=β1​⋅1−pp​⟹p=βps​−ps​+1βps​​

Equivalently, on the logit scale the model trained on resampled data is offset by −ln⁡β-\ln\beta−lnβ relative to the true logit, and the correction adds ln⁡β\ln\betalnβ back. A positive-class weight www in a well-specified model shifts the logit by roughly +ln⁡w+\ln w+lnw in the same spirit. The correction is exact only when the model is correctly specified for the posterior; for misspecified or flexible overfit models, recalibration on untouched validation data (Platt scaling or isotonic regression, see Model Evaluation & Validation) is more reliable than an analytic correction.

Interview angle

The sentence that distinguishes strong answers: "If scores will be read as probabilities (expected-loss decisions, ranking by expected value, thresholds from a cost matrix), the resampled model must be recalibrated on data with the true class prior. If only the ranking matters, resampling does not affect that argument."

#SMOTE pitfalls

  • Apply after the split and only to training folds. Synthesizing before splitting places points interpolated from validation rows into training, which is a form of leakage.
  • Distance-based. SMOTE interpolates in feature space, so it needs scaled numeric features and does not apply directly to categorical features (variants such as SMOTE-NC exist).
  • High dimensions and noise. Neighborhoods become uninformative as dimension grows (see the curse of dimensionality below), and interpolation between a minority point and a mislabeled neighbor can place synthetic samples inside the majority region.
  • Evaluate on the original distribution. The validation and test sets keep the true class ratio, or metrics no longer describe production.
  • Gains are often modest against class weights or threshold tuning with a strong learner; compare against those baselines rather than assuming resampling helps.

#Feature Selection

Selection reduces variance, cost, and latency, and can improve interpretability. Three families:

Family How it works Examples Strengths Limits
Filter Score each feature independently of the final model Correlation, mutual information, χ2\chi^2χ2, ANOVA F-test, variance threshold Fast, model-agnostic Ignores interactions and redundancy among features (two near-duplicate features both score well)
Wrapper Search subsets, scoring each with the actual model Forward selection, backward elimination, recursive feature elimination (RFE) Accounts for interactions and the model's behavior Expensive; high risk of overfitting the validation scores when many subsets are tried
Embedded Selection happens during training L1 / lasso (zeroes coefficients), tree split usage, elastic net Cheap, tuned to the model Model-specific; correlated features can be selected arbitrarily

Cautions:

  • Selection is part of the model. If features are chosen using labels on the full dataset and the model is then cross-validated, the CV estimate is optimistic, often severely when features far outnumber samples. Run selection inside each training fold.
  • Impurity-based tree importances are biased toward high-cardinality and continuous features. Permutation importance (shuffle one feature in held-out data and measure the drop) is less biased but can understate a feature when correlated copies exist, since the model leans on the other copy.
  • Stability matters: if selected subsets change a lot between folds, the ranking is unreliable.
  • Lasso selects among correlated features somewhat arbitrarily; elastic net groups them more smoothly. See Regularization.

#Feature Crosses and Interactions

A cross combines features so that a model can express their joint effect: a product x1x2x_1 x_2x1​x2​ for numeric features, or a Cartesian combination such as (city, hour_bucket) for categoricals.

  • Linear and logistic models cannot represent an interaction unless one is supplied, so crosses are the main way to add expressiveness.
  • Trees learn interactions through successive splits; neural networks learn them through hidden layers, so manual crosses help less (though explicit crosses over very sparse high-cardinality IDs can still help memorization).
  • Cost: crossing categorical features multiplies cardinality, so data per cell shrinks; hashing the crossed feature into a fixed number of buckets bounds the width, at the price of collisions.
  • Ratios and differences (clicks per impression, spend relative to the account's median) are a lightweight form of interaction, often more robust than raw products.

#Time and Lag Features

Time-aware features are the most frequent source of both strong signal and temporal leakage.

Feature type Construction Leakage guard
Lags Value at t−kt-kt−k Use only values with timestamps strictly before the prediction time
Rolling statistics Mean, std, min, max over a window Shift the window so that it excludes the current row (window ends at t−1t-1t−1)
Expanding / entity aggregates Count or mean over all history for a user Compute point-in-time, as of each row's timestamp, not from the final table
Calendar Hour, day of week, holiday flag Encode periodic features cyclically; holidays are known in advance and are safe
Recency / frequency Time since last event, events in the last 7 days Define "last" relative to the prediction timestamp
Differences and growth rates xt−xt−kx_t - x_{t-k}xt​−xt−k​, xt/xt−kx_t / x_{t-k}xt​/xt−k​ Same cutoff rule as lags; handle zeros in denominators

Two further rules apply. First, joins must be point-in-time ("as-of"): joining a slowly changing attribute (a user's plan tier) by key alone gives the current value rather than the value at the event, which leaks the future. Second, the label horizon defines the cutoff: with a label such as "churns within 30 days", features must be frozen at the prediction date and rows whose label window has not yet closed must be excluded or handled as censored. For stationarity and forecasting-specific validation, see Time Series Stationarity and Cross-Validation.

#Curse of Dimensionality

As the number of features ddd grows with fixed nnn, several things degrade:

  • Sparsity. To keep the same sample density, nnn must grow exponentially in ddd. Nonparametric estimators such as kNN or kernel methods converge at rates that deteriorate with ddd (for twice-differentiable targets, the mean squared error of kernel regression decays like n−4/(d+4)n^{-4/(d+4)}n−4/(d+4)).
  • Distance concentration. For many data distributions, the ratio between the distances to the nearest and farthest neighbors approaches 1 as ddd increases, so "nearest" carries little information for distance-based methods. The effect is stronger when features are independent and noisy than when the data lie near a low-dimensional manifold.
  • Volume geometry. Most of the volume of a ddd-dimensional ball lies in a thin shell near its surface, since the fraction of volume within radius (1−ϵ)r(1-\epsilon)r(1−ϵ)r is (1−ϵ)d(1-\epsilon)^d(1−ϵ)d.
  • Overfitting capacity. With d≥nd \ge nd≥n a linear model can interpolate the training labels; regularization, dimension reduction, or feature selection is needed.

Mitigations: regularization, feature selection, dimensionality reduction (PCA, autoencoders, embeddings), and more data. Real data frequently lies near a lower-dimensional structure, which is why high-dimensional models can still generalize, but the argument is empirical for each dataset rather than guaranteed.

Go deeper (optional)

Adding irrelevant features hurts distance-based methods quickly and hurts regularized or tree-based methods more slowly. A quick diagnostic is to append a few random noise columns and see whether the model assigns them importance; high noise-column importance signals overfitting.

#Pipeline Checklist: Leakage-Safe Workflow

Encapsulate every fitted step in a single pipeline object so that fitting, cross-validation, and serving share the same code.

  1. Define prediction time and label horizon. For each feature, write down when its value becomes known.
  2. Deduplicate and choose the split by time, group, or random-stratified according to the unit of generalization. Set aside the test set; do not touch it.
  3. Fit all preprocessing on the training portion only: imputers, scalers, encoders, vocabularies, binning edges, outlier bounds, feature selectors.
  4. Cross-fit any step that uses the label (target encoding, supervised selection, stacking features).
  5. Resample or reweight inside training folds only; keep validation and test at the natural class ratio.
  6. Tune hyperparameters, thresholds, and calibration on validation data; if probabilities matter, recalibrate on data with the true prior.
  7. Sanity-check for leaks: feature importance review, single-feature AUC, a time-forward or group-wise re-split, shuffled-label test (the score should fall to chance).
  8. Evaluate once on the test set with metrics matching the business decision.
  9. Ship the fitted pipeline as one artifact and log the training-data snapshot and statistics so that serving reproduces the same transforms (see ML in Production & Monitoring).
Interview angle

A concise way to summarize this checklist: "Every number the pipeline learns comes from training rows only, every step that uses the label is cross-fitted, and the validation scheme mirrors how the model will meet new data."

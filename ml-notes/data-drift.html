Data Drift vs Concept Drift

Say it in 30s: Data (covariate) drift is when input features P(X)P(X)P(X) change but the label relationship is stable — e.g. new traffic mix. Label (prior) drift is when P(Y)P(Y)P(Y) shifts. Concept drift is when P(Y∣X)P(Y \mid X)P(Y∣X) changes — the same features mean different outcomes after a UI change or new fraud pattern. Detection uses PSI/KS/JS on features or scores; the fix for concept drift is retrain or change the product, not just normalize inputs.

Key points

  • Covariate shift → calibration/slice review; concept drift → new labels / model refresh.
  • Prediction drift (score distribution) is an early warning when labels lag.
  • PSI on score/feature histograms vs a training reference — common alert thresholds ≈0.1\approx 0.1≈0.1 (watch) and 0.20.20.2 (act).
  • Monitor slices (country, app version), not only global averages.

Common follow-ups / traps

  • "Is seasonal traffic drift?" → Often covariate + prior shift; concept drift if user behavior given features changed.
  • "Retrain on every PSI alert?" → Tune thresholds; rollback bad deploys before mass retrain.

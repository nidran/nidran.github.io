PyTorch Cheatsheet

Lookups for shapes, losses, optimizers and the mistakes that cost hours. New to PyTorch? Start with the PyTorch Tutorial.

#Loss ↔ output ↔ target (the most common mismatch)

Task Last layer outputs Loss Target dtype and shape
Binary classification 1 logit, [B] nn.BCEWithLogitsLoss() float, [B]
Multi-class C logits, [B, C] nn.CrossEntropyLoss() long (class index), [B]
Multi-label C logits, [B, C] nn.BCEWithLogitsLoss() float, [B, C]
Regression 1 value, [B] nn.MSELoss() / nn.L1Loss() / nn.HuberLoss() float, [B]

Do not put softmax or sigmoid before CrossEntropyLoss / BCEWithLogitsLoss. They apply it internally. Apply it only at prediction time when you need probabilities.

#Tensor basics

x = torch.zeros(2, 3)                 # also ones, randn, arange, linspace
x.shape; x.dtype; x.device
x.view(3, 2)                          # same data, needs contiguous memory
x.reshape(3, 2)                       # view if possible, else copy
x.unsqueeze(0)                        # add dim → [1, 2, 3]
x.squeeze()                           # drop size-1 dims
x.permute(1, 0)                       # reorder dims
torch.cat([a, b], dim=0)              # join along an existing dim
torch.stack([a, b], dim=0)            # join along a NEW dim
x.to("cuda")                          # or .to(device); x.cpu().numpy() back to NumPy
x.float(); x.long()                   # dtype casts
x.detach()                            # cut from the autograd graph
x.item()                              # one-element tensor → Python number

#Training loop skeleton

model.train()
for xb, yb in loader:
    xb, yb = xb.to(device), yb.to(device)
    opt.zero_grad(set_to_none=True)
    loss = loss_fn(model(xb), yb)
    loss.backward()
    opt.step()

model.eval()
with torch.no_grad():
    ...                               # validation / inference

#model.eval() vs torch.no_grad()

model.eval() torch.no_grad()
Effect switches dropout off, batchnorm uses running stats stops building the autograd graph
Saves memory no yes
Need both at inference yes yes

#Optimizers and schedulers

Choice Typical use
AdamW(lr=1e-3, weight_decay=1e-2) strong default, transformers
SGD(lr=0.1, momentum=0.9) CNNs with a tuned schedule
CosineAnnealingLR(opt, T_max=epochs) smooth decay, step once per epoch
OneCycleLR fast training; step once per batch
ReduceLROnPlateau sched.step(val_loss)

Call opt.step() before sched.step().

#Useful layers

Layer Notes
nn.Linear(in, out) input [B, in] → [B, out]
nn.Conv2d(c_in, c_out, k) input [B, C, H, W]
nn.BatchNorm1d/2d behaves differently in train vs eval
nn.LayerNorm(d) standard in transformers
nn.Dropout(p) active only in train() mode
nn.Embedding(vocab, d) integer ids [B, T] → [B, T, d]
nn.LSTM(..., batch_first=True) set batch_first=True to keep [B, T, F]

#Initialization and freezing

nn.init.kaiming_normal_(layer.weight)        # ReLU networks
nn.init.xavier_uniform_(layer.weight)        # tanh / sigmoid

for p in backbone.parameters():              # freeze (transfer learning)
    p.requires_grad = False
opt = torch.optim.AdamW(filter(lambda p: p.requires_grad, model.parameters()), lr=1e-4)

#Saving and loading

torch.save(model.state_dict(), "model.pt")
model.load_state_dict(torch.load("model.pt", map_location="cpu", weights_only=True))

# resume training: also save optimizer and epoch
torch.save({"model": model.state_dict(), "opt": opt.state_dict(), "epoch": epoch}, "ckpt.pt")

#Speed and memory

# mixed precision on GPU
scaler = torch.amp.GradScaler("cuda")
with torch.autocast("cuda", dtype=torch.float16):
    loss = loss_fn(model(xb), yb)
scaler.scale(loss).backward()
scaler.step(opt); scaler.update()

# gradient accumulation (effective batch = batch_size * accum)
(loss / accum).backward()
if (i + 1) % accum == 0:
    opt.step(); opt.zero_grad(set_to_none=True)

DataLoader(ds, batch_size=64, num_workers=4, pin_memory=True)   # faster input pipeline

If you hit out-of-memory: lower the batch size, use mixed precision, accumulate gradients, or checkpoint activations.

#Pitfalls

Pitfall Fix
Forgot zero_grad() → gradients accumulate call it every step
Forgot model.eval() at inference dropout noise, wrong batchnorm stats
softmax before CrossEntropyLoss remove it; feed raw logits
Class targets as float for CrossEntropyLoss use long indices
Accumulating loss in a list for logging use loss.item() so the graph is freed
Model and data on different devices .to(device) both
In-place op breaks autograd avoid x += ... on tensors needed for backward
Non-reproducible runs torch.manual_seed(...); GPU ops may still vary

See also Gradient Descent, Regularization, PyTorch: Weights, Gradients & Backprop.
